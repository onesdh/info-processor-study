# 문제 2

## 문제

다음은 소프트웨어 테스트 기법 중 하나에 대한 설명이다.

소프트웨어 테스트의 구조 기반(화이트박스) 기법 중 하나로,

결정 포인트(Decision Point) 내에 존재하는 모든 개별 조건식(Atomic Condition) 을 대상으로 하는 커버리지 기준이 있다.

하나의 결정문(예: if (A && B) 또는 if (X &gt; 10 || Y == 0)) 안에는

여러 개의 조건식이 포함될 수 있는데 이 커버리지는

각각의 조건식이 True와 False 두 가지 경우를 모두 한 번 이상 만족하도록

테스트 케이스를 설계해야 한다.

즉, 모든 개별 조건이 두 방향의 결과를 거쳐야 “커버되었다”고 판단하지만

그렇다고 해서 전체 결정식(Decision Expression) 의 결과(True/False)가

모두 수행된다고 보장하지는 않는다.

## 1. 문제에서 묻는 것
"결정문 안의 **개별 조건식**이 각각 True/False를 모두 만족해야 하지만, **전체 결정의 결과가 모두 나온다는 보장은 없다**"는 화이트박스 커버리지가 무엇인지 고르는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 화이트박스 테스트와 커버리지
- **화이트박스 테스트**: 소스 코드 **내부 구조(논리 경로)** 를 보면서 테스트하는 방식.
- **커버리지(Coverage, 범위)**: 코드의 **얼마만큼을 테스트가 실행했는가**를 재는 기준.

### (2) 용어: 결정과 조건
```c
if (A && B) { ... }     // 전체 식 (A && B) = 결정(Decision)
                        // A, B 각각           = 조건(Condition)
```
- **결정(Decision)**: if 안의 **전체 논리식**. 결과는 True 또는 False.
- **조건(Condition)**: 결정을 이루는 **개별 논리식**(더 쪼갤 수 없는 단위).

### (3) 커버리지 종류 (약 → 강)
| 커버리지 | 만족 기준 |
|---|---|
| **문장(구문)** | 모든 **문장**을 1번 이상 실행 |
| **결정(분기)** | **결정 전체**가 True/False 각 1번 |
| **조건** | **각 조건식**이 True/False 각 1번 |
| 조건/결정 | 결정 커버리지 + 조건 커버리지 **둘 다** 만족 |
| 변경 조건/결정(MC/DC) | **각 조건이 단독으로** 결정 결과에 영향을 주는 것을 보임 |
| **다중 조건** | 조건들의 **모든 True/False 조합** |

## 3. 왜 "조건"인가? (예로 이해)
`if (A && B)` 에서 테스트 2개: **(A=T, B=F)**, **(A=F, B=T)**
| 테스트 | A | B | A&&B(결정) |
|---|:--:|:--:|:--:|
| 1 | T | F | **F** |
| 2 | F | T | **F** |

- A: T, F 모두 나옴 ✅ / B: T, F 모두 나옴 ✅ → **조건 커버리지 만족**
- 그러나 **결정 결과는 F만** 나옴 ❌ → **결정(분기) 커버리지는 불만족**

문제의 말 "개별 조건은 두 방향을 거치지만, 결정식의 True/False가 모두 수행된다고 보장하지 않는다"가 바로 이 상황이다.

## 4. 보기 비교
| 보기 | 설명 | 정답? |
|---|---|:--:|
| ㅇ **조건** | **개별 조건식**의 T/F | ✅ |
| ㄴ/ㅅ 결정=분기 | **전체 결정**의 T/F | ❌ |
| ㄷ 조건/결정 | 조건+결정 **모두** 보장 | ❌ |
| ㄹ MC/DC | 각 조건이 결과에 독립 영향 | ❌ |
| ㅁ 다중 조건 | 모든 조합 | ❌ |
| ㅂ 문장 | 모든 문장 실행 | ❌ |

> **정답: ㅇ. 조건(Condition)**

## 5. 암기 포인트
- 결정(분기) = **전체 식**의 T/F, 조건 = **부분(개별) 식**의 T/F.
- 조건/결정 커버리지 = 두 가지를 **동시에** 만족하는 상위 개념.
