# 문제 4

## 문제

다음은 오류검출 방식을 설명하는 내용이다. 설명의 빈칸 (①)~(⑤) 에 들어갈 알맞은 용어를 &lt;보기&gt;에서 고르시오.

(①) 코드는 전송 데이터에 여러 개의 검사 비트를 추가하여 오류를 검출하고 수정까지 가능한 방법이다.

이 코드는 재전송 없이 수신 측에서 자체 수정하는 (②) 방식에 속한다.

이에 반해 오류 발생 시 송신 측에 재전송을 요구하는 방식은 (③)이라 하며, 여기에 포함되는 대표적 검출 기법으로 (④) 검사와 (⑤) 검사가 있다.

(④) 검사는 데이터 블록 끝에 1비트 검사 비트를 추가하여 오류를 검출한다.

(⑤) 검사는 송신측과 수신측이 동일한 특정 다항식을 사용하여 오류를 검출한다.

## 1. 문제에서 묻는 것
**오류 검출·정정 방식**의 분류(FEC / BEC)와 대표 기법(해밍, 패리티, CRC)을 연결하는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 왜 오류 제어가 필요한가?
통신 중 잡음 등으로 **0이 1로 바뀌는** 오류가 생긴다. 이를 **발견(검출)** 하거나 **고치는(정정)** 기술이 필요하다.

### (2) 큰 분류
```text
                    오류 제어
            ┌──────────┴───────────┐
   FEC (전진 오류 수정)         BEC (후진 오류 수정 = ARQ)
   수신측이 스스로 "고침"        오류를 "발견"하면 재전송 요구
   재전송 없음                   재전송(NAK) 필요
   대표: 해밍 코드               대표: 패리티 검사, CRC
```
| 구분 | 의미 | 대표 기법 |
|---|---|---|
| **FEC** (Forward Error Correction) | 수신 측이 **재전송 없이 직접 정정** | **해밍 코드** |
| **BEC** (Backward Error Correction) = ARQ | 오류 **검출 후 송신 측에 재전송 요구** | **패리티**, **CRC**, 체크섬 |

### (3) 기법별 특징
| 기법 | 방법 | 능력 |
|---|---|---|
| **패리티(Parity)** | 데이터 끝에 **1비트** 검사 비트 추가(1의 개수를 짝수/홀수로 맞춤) | **1비트 오류 검출**만 가능 |
| **CRC** | 송·수신측이 **같은 다항식**으로 나눈 나머지를 FCS로 붙임 | **버스트(연속) 오류** 검출에 강함, 검출만 |
| **해밍 코드** | 데이터 사이에 **여러 검사 비트** 삽입 | **1비트 오류의 위치를 찾아 정정** |

패리티 예: 데이터 `1011` (1이 3개) → **짝수 패리티**면 검사 비트 `1`을 붙여 `10111` (1이 4개).

## 3. 문제 풀이
| 빈칸 | 단서 | 정답 |
|---|---|---|
| ① | **여러 검사 비트**로 오류 검출+**수정** | ㉧ **Hamming** |
| ② | **재전송 없이** 수신 측이 자체 수정 | ㉡ **FEC** |
| ③ | **송신 측에 재전송 요구** | ㉢ **BEC** |
| ④ | 데이터 끝에 **1비트** 검사 비트 | ㉤ **Parity** |
| ⑤ | **동일한 특정 다항식**으로 검출 | ㉠ **CRC** |

(보기 ㉣ NAK = 부정 응답(재전송 요구 신호), ㉥ MD5 = 해시 함수, ㉦ BCD = 이진화 십진수 → 무관)

> **정답: ① Hamming ② FEC ③ BEC ④ Parity ⑤ CRC**

## 4. 암기 포인트
- **FEC = 해밍(수정)**, **BEC = 패리티·CRC(검출 후 재전송)**.
- 패리티 = **1비트**, CRC = **다항식**.
