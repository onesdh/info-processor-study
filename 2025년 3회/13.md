# 문제 13

## 문제

다음은 인증 및 자원 접근 방식에 대한 설명이다. 알맞은 단어를 작성하시오.

사용자가 새로운 사이트에 가입하지 않고 평소에 이용하던 서비스의 계정으로 로그인할 수 있게 해주는 기술이다.

사용자의 비밀번호는 절대 전달되지 않으며 사용자가 승인한 범위에 대해서만 접근 권한이 위임된다.

이 방식은 직접 인증(Authentication)을 수행하지 않고 "인가(Authorization)" 절차를 통해 접근 권한을 제3자에게 부여한다.

인증 완료 후, 서비스 제공자는 Access Token을 발급하며 애플리케이션은 이 토큰을 이용해 API를 호출하여 필요한 정보에 접근한다.

대표적인 예는 소셜 로그인이며 SSO(Single Sign-On)과 달리 동일 시스템 내 인증이 아니라 서로 다른 서비스 간의 권한 위임에 초점이 맞춰져 있다.

## 1. 문제에서 묻는 것
"기존 서비스 계정으로 로그인, **비밀번호는 전달되지 않고**, **Access Token**으로 **인가(권한 위임)**" → 어떤 기술인지 묻는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 인증 vs 인가
| 용어 | 질문 | 예 |
|---|---|---|
| **인증(Authentication)** | **누구**인가? | 로그인(아이디/비번 확인) |
| **인가(Authorization)** | **무엇을 할 수 있나?** | 파일 읽기만 허용, 사진 조회만 허용 |

### (2) OAuth (Open Authorization)
**제3자 애플리케이션이 내 비밀번호를 받지 않고도, 내가 허락한 범위 안에서만 내 정보에 접근**하도록 **권한을 위임**하는 **개방형 인가 표준**이다.

### (3) 동작 흐름 (예: "구글로 로그인")
```text
 ① 사용자 ──"구글 계정으로 로그인"──▶ 앱(제3자)
 ② 앱 ──▶ 구글 인증 서버로 이동 (사용자가 직접 구글에 로그인, 앱은 비번을 못 봄)
 ③ 사용자 ──"이 앱에 프로필·이메일 접근을 허용"──▶ 구글
 ④ 구글 ──▶ 앱에 Access Token 발급
 ⑤ 앱 ──Access Token──▶ 구글 API 호출 (허용된 범위 정보만 응답)
```
핵심: **비밀번호는 앱에 전달되지 않는다.** 앱은 **토큰**만 가진다. 토큰은 **범위(scope)와 유효기간**이 제한된다.

### (4) SSO와의 차이
| 구분 | OAuth | SSO(Single Sign-On) |
|---|---|---|
| 초점 | **권한 위임(인가)** | **한 번 로그인으로 여러 시스템 사용(인증)** |
| 범위 | **서로 다른 서비스 간** | 주로 **동일 조직/시스템 내** |

## 3. 문제 풀이
| 문제 단서 | OAuth |
|---|---|
| 기존 서비스 계정으로 로그인, 소셜 로그인 | OAuth의 대표 활용 |
| 비밀번호 전달 X, 승인한 범위만 접근 | 위임·범위(scope) |
| 직접 인증이 아니라 **인가**로 권한 부여 | OAuth는 인가 프레임워크 |
| Access Token으로 API 호출 | 토큰 기반 |

> **정답: OAuth**

## 4. 암기 포인트
- **OAuth = 인가(권한 위임) + Access Token**, 소셜 로그인의 기반.
- (참고) OpenID Connect는 OAuth 위에 **인증** 기능을 얹은 표준.
