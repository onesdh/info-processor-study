# 문제 16

## 문제

관계형 데이터베이스 개념에 대한 설명이다. 빈칸에 들어갈 용어를 &lt;보기&gt;에서 골라 순서대로 쓰시오.

ㄱ. 테이블에서 한 행(Row)을 의미하며, 하나의 레코드를 구성하는 요소

ㄴ. 실제 데이터가 저장되어 있는 테이블의 내용 전체를 의미하며, 데이터의 상태를 나타낸다.

ㄷ. 테이블에 저장된 행(Row)의 총 개수를 의미한다.

## 1. 문제에서 묻는 것
**릴레이션(테이블) 관련 용어**를 설명과 연결하는 문제다. 튜플 / 인스턴스 / 카디널리티를 구분해야 한다.

## 2. 먼저 알아야 할 개념
### (1) 릴레이션 구조
```text
          속성(Attribute) = 열(Column)
          ┌────────┬────────┬────────┐
          │  학번  │  이름  │  학과  │   ← 스키마(Schema): 구조 정의
          ├────────┼────────┼────────┤
 튜플 ─▶  │ 20201  │ 홍길동 │ 컴공   │
(Tuple    │ 20202  │ 김철수 │ 전자   │   ← 인스턴스(Instance): 실제 데이터
= 행/Row) │ 20203  │ 이영희 │ 컴공   │
          └────────┴────────┴────────┘
          차수(Degree) = 열의 수 = 3
          카디널리티(Cardinality) = 행의 수 = 3
```
### (2) 용어 정리
| 용어 | 의미 |
|---|---|
| **튜플(Tuple)** | **행(Row)**, 레코드 하나 |
| **속성(Attribute)** | **열(Column)**, 데이터의 특성 |
| **도메인** | 속성이 가질 수 있는 값의 범위 |
| **스키마(Schema)** | 테이블의 **구조 정의**(내포, 잘 안 변함) |
| **인스턴스(Instance)** | 특정 시점에 저장된 **실제 데이터 전체**(외연, 자주 변함) |
| **차수(Degree)** | **속성(열)의 개수** |
| **카디널리티(Cardinality)** | **튜플(행)의 개수** |

## 3. 문제 풀이
| 설명 | 정답 |
|---|---|
| ㄱ. 테이블의 **한 행**, 하나의 레코드 | **튜플** |
| ㄴ. 실제 데이터가 저장된 **내용 전체**, 데이터의 **상태** | **인스턴스** |
| ㄷ. 저장된 **행의 총 개수** | **카디널리티** |

(보기 스키마 = 구조, 속성 = 열, 차수 = 열의 수 → 모두 오답)

> **정답: ㄱ. 튜플 / ㄴ. 인스턴스 / ㄷ. 카디널리티**

## 4. 암기 포인트
- **차수 = 열(속성) 수**, **카디널리티 = 행(튜플) 수** — "차(열)·카(행)" 헷갈리기 쉽다.
- 스키마(구조·정적) vs 인스턴스(내용·동적).
