# 문제 1

## 문제

다음은 UML (    ) 다이어그램이다. 아래 내용을 보고 다이어그램의 관계를 확인하여 명칭을 작성하시오.

(   ) 다이어그램이란

시스템을 폴더 모양의 (   ) 단위로 구분하여 구성 요소 간의 관계를 표현하는 UML 구조 다이어그램이다.

하나의 (   ) 안에는 여러 클래스나 하위 (   ) 가 포함될 수 있으며,

(   ) 간에는 «import», «access», «merge» 등의 관계를 통해 의존성(Dependency) 을 표현한다.

이 다이어그램은 코드의 실제 구조(폴더 구조)와 비슷하게 표현되기 때문에

소프트웨어의 모듈화, 재사용성, 의존 관계를 시각적으로 설계할 때 자주 사용된다.

## 1. 문제에서 묻는 것
"폴더 모양 단위로 시스템을 나누고 «import», «access», «merge» 의존 관계를 표현하는 UML 구조 다이어그램"의 이름을 쓰는 문제다.

## 2. 먼저 알아야 할 개념
### (1) UML이란?
**Unified Modeling Language**. 소프트웨어 설계를 **그림으로 표현하는 표준 표기법**이다. 크게 두 종류로 나뉜다.

| 구분 | 무엇을 보여주나 | 다이어그램 |
|---|---|---|
| **구조(정적) 다이어그램** | 시스템의 **뼈대(구성 요소와 관계)** | 클래스, 객체, 컴포넌트, 배치, 복합체 구조, **패키지** |
| **행위(동적) 다이어그램** | 시간에 따른 **동작·흐름** | 유스케이스, 시퀀스, 커뮤니케이션, 상태, 활동, 타이밍 |

### (2) 패키지(Package)
클래스·인터페이스 등 **관련된 요소를 폴더처럼 묶은 단위**다. 프로그램이 커지면 클래스가 수백 개가 되므로 **의미 있는 묶음**으로 정리해야 한다.
```text
  ┌──────┐
  │ UI   │ ─ «import» ─▶ ┌──────────┐ ─ «access» ─▶ ┌────────┐
  └──────┘               │ Service  │               │  DB    │
 (탭 달린 폴더 모양)      └──────────┘               └────────┘
```
### (3) 패키지 간 의존 관계(스테레오타입)
| 표기 | 의미 |
|---|---|
| «import» | 다른 패키지의 요소를 **가져와** 이름 그대로 사용 (공개 요소) |
| «access» | 다른 패키지 요소를 **참조만** 함 (이름 재노출 없음) |
| «merge» | 두 패키지의 **내용을 병합** |

## 3. 문제 풀이
| 문제 단서 | 해당 |
|---|---|
| **폴더 모양** 단위로 시스템을 구분 | 패키지 표기(탭 달린 폴더) |
| 한 개 안에 클래스나 **하위 (   )** 포함 | 패키지 안에 패키지 |
| «import», «access», «merge» 의존 | 패키지 간 관계 |
| 코드의 폴더 구조와 비슷, 모듈화·의존 관계 설계 | 패키지 다이어그램 |

> **정답: 패키지**

## 4. 암기 포인트
- 폴더 모양 + import/access/merge = **패키지 다이어그램** (구조 다이어그램).
- 비슷한 구조 다이어그램: **클래스**(클래스 내부 구조), **컴포넌트**(실행 단위·인터페이스), **배치**(하드웨어에 배치).
