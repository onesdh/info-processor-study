# 문제 18

## 문제

시스템 객체의 접근을 개인 또는 그룹의 식별자에 기반을 둔 방법, 어떤 종류의 접근 권한을 가진 사용자가 다른 사용자에 자신의 판단에 따라 권한을 허용하는 접근제어 방식은 ?

<details>
<summary><strong>정답 보기</strong></summary>

임의적 접근 통제 or DAC (Discretionary Access Control)

&nbsp;접근 통제는 사람이나 프로세스가 시스템이나 파일에 접근 여부를 허가하거나 거부하는 기능을 말합니다.

서버 접근통제 유형 - 임의적 접근통제 / 강제적 접근통제 / 역할 기반 접근통제

임의적 접근 통제(DAC - Discretionary Access Control) : 시스템 객체에 대한 접근을 사용자나 그룹의 신분을 기준으로 제한하는 방법

강제적 접근 통제(MAC - Mandatory Access Control) : 미리 정해진 정책과 보안 등급에 의거하여 주체에게 허용된 접근 권한과 객체에게 부여된 허용 등급을 비교하여 접근을 통제하는 모델

역할기반 접근 통제(RBAC - Role Based Access Control) : DAC와 MAC의 단점을 보완한 방식으로 멀티 프로그래밍 환경에서의 보완 처리를 위해 제안되었으며 사용자에게 할당된 역할에 기반하여 접근을 통제하며 중앙에서 집중적으로 관리

</details>

<summary><strong>상세 해설</strong></summary>

## 1. 문제에서 묻는 것
"시스템 객체의 접근을 **개인 또는 그룹의 식별자(신분)** 에 기반, 접근 권한을 가진 사용자가 **자신의 판단**으로 다른 사용자에게 권한 허용" → 접근통제 방식을 쓰는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 접근통제 3가지
| 모델 | 판단 기준 | 정책 결정자 | 특징 |
|---|---|---|---|
| **DAC** (임의적) | **주체·그룹의 신분(Identity)** | **자원의 소유자**(권한을 가진 사용자가 재량으로 부여) | 유연하지만 보안성 낮음 |
| **MAC** (강제적) | 정해진 **정책·보안 등급** 비교 | 중앙 관리자 | 가장 엄격, 군사·기밀 |
| **RBAC** (역할 기반) | **역할(직무)** | 중앙에서 집중 관리 | DAC·MAC의 단점 보완, 조직에 적합 |

### (2) DAC 예
```text
 파일 소유자 철수가 "영희에게 읽기 권한 허용"   ← 소유자의 판단으로 권한을 넘김
 (리눅스 chmod, 윈도우 파일 속성)
```
## 3. 문제 풀이
| 단서 | DAC |
|---|---|
| 접근을 **개인·그룹의 식별자(신분)** 에 기반 | ✅ |
| 접근 권한을 가진 사용자가 **자신의 판단**으로 다른 사용자에게 권한 허용 | ✅ |

> **정답: 임의적 접근 통제 (DAC, Discretionary Access Control)**

</details>
