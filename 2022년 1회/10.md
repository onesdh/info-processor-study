## 문제

다음은 분석도구에 대한 설명으로 보기에 알맞는 답을 작성하시오.  
(실제 기출문제에서는 답의 보기가 주어집니다.(오답 중, running analysis 등..))

1. 소스 코드의 실행 없이, 코드의 의미를 분석해 결함을 찾아내는 원시적 코드 분석 기법  
2. 소스 코드를 실행하여 프로그램 동작이나 반응을 추적하고 코드에 존재하는 메모리 누수, 스레드 결함 등을 분석

## 1. 문제에서 묻는 것
코드 분석 도구를 **정적 분석(static)** 과 **동적 분석(dynamic)** 으로 구분하는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 정적 분석 vs 동적 분석
| 구분 | **정적 분석(Static Analysis)** | **동적 분석(Dynamic Analysis)** |
|---|---|---|
| 프로그램 **실행** | **실행 없이** 소스 코드만 분석 | 프로그램을 **실행하며** 분석 |
| 찾는 것 | 코딩 규칙 위반, 구조 결함, 코드 의미 상의 문제, **보안 취약 패턴** | **메모리 누수**, **스레드 결함**, 성능 문제, 실행 중 오류 |
| 시점 | **개발 초기**에 적용 가능 | **실행 가능한 상태**가 되어야 함 |
| 비유 | 책을 **읽고** 오탈자 찾기 | 음식을 **먹어 보고** 맛 평가 |
| 도구 예 | pmd, cppcheck, checkstyle, SonarQube, FindBugs | Valgrind, Avalanche, 프로파일러 |

```text
 정적: 소스 코드 ──(실행 안 함)──▶ 분석 도구 ──▶ 결함 목록
 동적: 소스 코드 ──실행──▶ 동작·메모리·스레드 추적 ──▶ 결함 목록
```
## 3. 문제 풀이
| 번호 | 단서 | 정답 |
|---|---|---|
| 1 | **소스 코드를 실행하지 않고**, 코드의 의미를 분석해 결함을 찾는 **원시적** 기법 | **static (정적 분석)** |
| 2 | 소스 코드를 **실행**하여 동작·반응 추적, **메모리 누수·스레드 결함** 분석 | **dynamic (동적 분석)** |

> **정답: 1. static 2. dynamic**

## 4. 암기 포인트
- **정적 = 실행 ✕(코드 읽기)**, **동적 = 실행 ○(메모리 누수·스레드)**.
