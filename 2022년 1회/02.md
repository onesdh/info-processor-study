## 1. 문제에서 묻는 것
**데이터베이스 회복(Recovery)** 기법인 **Redo**와 **Undo**를 구분하는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 트랜잭션과 회복
**트랜잭션(Transaction)** 은 "모두 성공하거나 모두 취소"되어야 하는 **작업 단위**다(예: 계좌 이체 = 출금 + 입금). 시스템 장애가 나면 DB를 **일관된 상태로 복구**해야 한다. 이때 **로그(log)** 를 이용한다.

### (2) Redo와 Undo
| 구분 | **Redo (재실행)** | **Undo (취소)** |
|---|---|---|
| 대상 | 장애 전 **이미 완료(COMMIT)** 되었으나 디스크에 반영 안 된 작업 | 장애 시점에 **아직 완료되지 않은** 작업 |
| 동작 | 로그를 보고 **그 작업을 다시 수행**(앞으로 되감아 재실행) | 로그를 보고 **작업을 되돌려** 이전 상태 복원 |
| 목적 | **지속성(Durability)** 보장 | **원자성(Atomicity)** 보장 |

```text
  시간 ─────────────────────────────────▶   장애 발생 ✖
  T1: [시작 ... 커밋]  ✔(완료)                      → Redo (재실행: 결과를 다시 반영)
  T2: [시작 ......... (미완료)]                      → Undo (롤백: 취소해서 원래대로)
```
`ROLLBACK`은 사용자가 트랜잭션을 취소하는 명령으로 Undo와 같은 효과(보기의 오답으로 등장).

## 3. 문제 풀이
| 번호 | 설명 | 정답 |
|---|---|---|
| 1 | **로그**를 기록해 두었다가 **이전 상태로 돌아간 후**, 실패 전까지의 과정을 **그대로 다시 따라가는** 것 | **Redo** |
| 2 | 작업을 **취소**하여 트랜잭션을 **이전 상태로 되돌리는** 것 | **Undo** |

> **정답: 1. redo / 2. undo**

## 4. 암기 포인트
- **Redo = 다시 실행**(완료된 작업 반영), **Undo = 되돌림**(미완료 작업 취소).
- 둘 다 **로그**를 이용한다.
