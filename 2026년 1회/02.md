# 문제 02

## 문제

다음 설명에 해당하는 디자인 패턴의 유형을 괄호( ) 안에 쓰시오.

• ( ㄱ ) 패턴은 기능의 클래스 계층과 구현의 클래스 계층을 연결  
• ( ㄴ ) 패턴은 한 객체의 상태가 바뀌면 그 객체에 의존

<details>
<summary><strong>정답 보기</strong></summary>

ㄱ. Bridge

ㄴ. Observer

</details>



<details>
<summary><strong>상세 해설</strong></summary>

## 1. 문제에서 묻는 것
설명을 보고 **디자인 패턴 이름**을 쓰는 문제다. (ㄱ) 기능 계층과 구현 계층을 **연결**, (ㄴ) 한 객체 상태가 바뀌면 **의존하는 객체에 알림**.

## 2. 먼저 알아야 할 개념
### (1) 디자인 패턴과 GoF 분류
| 분류 | 관심사 | 대표 패턴 |
|---|---|---|
| 생성 | 객체 생성 방법 | 추상 팩토리, 팩토리 메소드, 빌더, 프로토타입, 싱글톤 |
| **구조** | 클래스·객체 **조합** | 어댑터, **브리지**, 컴포짓, 데코레이터, 퍼사드, 플라이웨이트, 프록시 |
| **행위** | 객체 간 **협력·책임** | **옵저버**, 스트래티지, 템플릿 메소드, 이터레이터, 커맨드 등 |

### (2) 브리지(Bridge) — 구조 패턴
"**기능(추상화)** 클래스 계층"과 "**구현** 클래스 계층"을 **분리하고 다리(bridge)로 연결**해 둘을 독립적으로 확장하게 한다.

예) 리모컨(기능) × TV 종류(구현)
```text
 기능 계층              구현 계층
 Remote ─────────────▶ Device (인터페이스)
  ├ BasicRemote          ├ SonyTV
  └ AdvancedRemote       └ LgTV
 (리모컨을 늘려도 TV 코드 수정 없음, TV를 늘려도 리모컨 코드 수정 없음)
```
상속만 쓰면 `SonyBasicRemote`, `LgAdvancedRemote`… 처럼 조합마다 클래스가 폭증한다. 브리지는 이를 막는다.

### (3) 옵저버(Observer) — 행위 패턴
한 객체(**Subject**)의 상태가 변하면 그에 **의존하는 여러 객체(Observer)** 에게 **자동으로 알림**을 보내 갱신하게 한다. (발행-구독, 이벤트 리스너)
```text
        ┌───────────── 상태 변경 ─────────────┐
 Subject(주제) ──notify()──▶ Observer A (갱신)
                         └─▶ Observer B (갱신)
```
예) 유튜브 구독 알림, 주가가 변하면 여러 화면 갱신.

## 3. 문제 풀이
| 설명 | 패턴 |
|---|---|
| (ㄱ) 기능 클래스 계층과 구현 클래스 계층을 연결 | **Bridge** |
| (ㄴ) 한 객체의 상태 변화 → 의존 객체에 통지 | **Observer** |

> **정답: ㄱ. Bridge / ㄴ. Observer**

## 4. 암기 포인트
- **브리지 = 구조 패턴**(기능·구현 분리), **옵저버 = 행위 패턴**(상태 변화 알림).
- 비슷한 이름 구분: 어댑터(인터페이스 변환), 데코레이터(기능 동적 추가), 프록시(대리 접근).
