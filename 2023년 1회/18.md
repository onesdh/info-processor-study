# 문제 18

## 문제

다음은 스키마와 관련된 내용이다. 각 괄호안에 알맞는 답을 작성하시오.

(보기가 있습니다.)

| 구분 | 내용 |
|---|---|
| (   1   ) 스키마 | - 사용자나 응용 프로그래머가 개인의 입장에서 필요한 데이터베이스의 논리적 구조를 정의한다. <br>- 전체 데이터베이스의 한 논리적인 부분으로 볼 수 있기 때문에 서브 스키마라고도 한다. <br>- 하나의 데이터베이스 시스템에는 여러 개의 외부 스키마가 존재할 수 있다. <br>- 하나의 외부 스키마를 여러개의 응용 프로그램 혹은 사용자가 공유할 수 있다. |
| (   2   ) 스키마 | - 데이터베이스의 전체적인 논리적 구조로, 모든 응용 프로그램이나 사용자들이 필요로 하는 데이터를 종합한 조직 전체의 데이터베이스로 하나만 존재한다. <br>- 개체 간의 관계(Relationship)와 제약 조건을 나타내고 데이터베이스의 접근 권한, 보안 및 무결성 규칙에 관한 명세를 정의한다. <br>- 데이터베이스 파일에 저장되는 데이터의 형태를 나타내는 것이다. <br>- 기관이나 조직체의 관점에서 데이터베이스를 정의한 것이다 |
| (   3   ) 스키마 | - 물리적인 저장장치 입장에서 데이터가 저장되는 방법을 기술한 것이다. <br>- 실제 데이터베이스에 저장될 레코드의 물리적인 구조를 정의한다.  <br>- 저장 데이터 항목의 표현방법, 내부 레코드의 물리적 순서, 인덱스 유/무 등을 나타낸다. <br>- 시스템 프로그래머나 시스템 설계자가 관리한다. |

## 1. 문제에서 묻는 것
**DB 3단계 스키마**(외부, 개념, 내부)를 설명으로 구분하는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 3단계 스키마 구조
같은 DB를 **사용자 관점 → 조직 관점 → 저장 관점** 세 층으로 나눠 **데이터 독립성**을 확보한다.
```text
   사용자 A      사용자 B      응용 프로그램 C
      │            │              │
 ┌────▼────────────▼──────────────▼────┐
 │  외부 스키마 (뷰, 서브 스키마)  ← 여러 개    │   "사용자가 보는 데이터"
 └──────────────────┬───────────────────┘
                    │  외부/개념 사상
 ┌──────────────────▼───────────────────┐
 │  개념 스키마 (전체 논리 구조) ← 1개          │   "조직 전체의 데이터베이스"
 └──────────────────┬───────────────────┘
                    │  개념/내부 사상
 ┌──────────────────▼───────────────────┐
 │  내부 스키마 (물리적 저장 구조) ← 1개         │   "디스크에 어떻게 저장하나"
 └──────────────────────────────────────┘
```
| 스키마 | 관점 | 개수 | 내용 |
|---|---|:---:|---|
| **외부** | **사용자/응용 프로그래머** | **여러 개** | 개인이 필요한 논리적 구조, **서브 스키마**, 뷰 |
| **개념** | **조직 전체(DBA)** | **1개** | 전체 논리 구조, **개체 간 관계·제약조건·접근 권한·보안·무결성** 규칙 |
| **내부** | **저장장치(시스템 설계자)** | 1개 | 물리적 저장 구조, **레코드 순서, 인덱스, 저장 방법** |

## 3. 문제 풀이
| 번호 | 단서 | 정답 |
|---|---|---|
| (1) | **사용자/응용 프로그래머** 개인 입장, **서브 스키마**, 여러 개 존재 | **외부** |
| (2) | **전체적인 논리 구조**, 조직 전체 데이터베이스로 **하나만**, 관계·제약조건·보안·무결성 규칙 | **개념** |
| (3) | **물리적 저장장치** 입장, 레코드의 **물리적 구조**, **인덱스 유/무**, 시스템 프로그래머가 관리 | **내부** |

> **정답: 1. 외부 / 2. 개념 / 3. 내부**

## 4. 암기 포인트
- **외부(사용자, 여러 개) – 개념(조직 전체, 1개) – 내부(물리 저장)**.
- 외부 스키마 = **뷰(View)**, 내부 스키마 = **인덱스·저장 구조**.
