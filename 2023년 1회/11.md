# 문제 11

## 문제

다음은 디자인 패턴에 관한 설명이다. 설명에 내용에 알맞는 답을 고르시오.

(생성/구조/행위 별로 표형태의 보기가 있습니다. ex: Builder, Bridge  등)

- 다른 무언가와 이어지는 인터페이스 역할을 하는 클래스를 의미한다.

- 실제 객체를 호출하면 행위를 중간에 가로채서 다른 동작을 수행하는 객체로 변경한다.

- 객체를 정교하게 제어해야 하거나 객체 참조가 필요한 경우 사용한다.

- 분리된 객체를 위임함으로써 대리 작업을 중간 단계에 삽입할 수도 있으며 분리된 객체를 동적으로 연결함으로써 객체의 실행 시점을 관리할 수도 있다.

## 1. 문제에서 묻는 것
"**대리 객체**로 **접근을 중간에서 가로채** 다른 동작 수행, 객체 참조 제어, 동적 연결로 실행 시점 관리" → 어떤 디자인 패턴인지 쓰는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 프록시(Proxy) 패턴 (구조 패턴)
**실제 객체(Real Subject) 앞에 같은 인터페이스를 가진 대리인(Proxy)을 두고**, 클라이언트의 요청을 **대신 받아 접근을 제어**한다.
```text
 클라이언트 ──▶ [ Proxy ] ──(허용·필요 시)──▶ [ 실제 객체 ]
                 ├ 접근 권한 확인
                 ├ 생성 지연(Lazy Loading)
                 ├ 캐싱, 로깅
                 └ 원격 객체 대리(RMI)
```
비유: **비서**를 거쳐서만 사장을 만날 수 있는 구조.

### (2) 프록시의 종류
| 종류 | 역할 |
|---|---|
| 가상 프록시 | 무거운 객체 생성을 **필요할 때까지 지연** |
| 보호 프록시 | **접근 권한** 검사 |
| 원격 프록시 | **다른 서버의 객체**를 로컬처럼 사용 |
| 캐싱 프록시 | 결과 **캐시** |

### (3) 혼동 쉬운 구조 패턴
| 패턴 | 목적 |
|---|---|
| **프록시** | **접근 제어** (같은 인터페이스) |
| 어댑터 | 인터페이스 **변환** |
| 데코레이터 | 기능 **동적 추가** |
| 퍼사드 | 복잡한 서브시스템에 **단순한 창구** |

## 3. 문제 풀이
| 단서 | Proxy |
|---|---|
| 다른 것과 이어지는 **인터페이스 역할** 클래스 | ✅ |
| 실제 객체 호출 시 **행위를 중간에 가로채** 다른 동작 수행 | ✅ |
| 객체를 정교하게 제어, 참조 필요 시 사용 | ✅ |
| **대리 작업을 중간 단계에 삽입**, 객체의 **실행 시점 관리** | ✅ |

> **정답: Proxy (프록시)**
