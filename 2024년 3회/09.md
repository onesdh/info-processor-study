# 문제 09

## 문제

다음은 URL 구조에 관한 문제이다 . 아래  보기의 순서대로 URL에 해당하는 번호를 작성하시오.

보기

query : 서버에 전달할 추가 데이터  
path : 서버 내의 특정 자원을 가리키는 경로

scheme : 리소스에 접근하는 방법이나 프로토콜

authority : 사용자 정보, 호스트명, 포트 번호

fragment : 특정 문서 내의 위치

## 1. 문제에서 묻는 것
URL을 구성 요소로 나눴을 때, **보기의 순서대로** 해당하는 번호((1)~(5))를 쓰는 문제다.

## 2. 먼저 알아야 할 개념
### (1) URL 구조
```text
  foo://localhost:8080/over/there?name=ferret#nose
  └(1)┘ └────── (2) ──────┘└── (3) ──┘└── (4) ──┘└(5)┘
  scheme     authority          path       query    fragment
```
| 구성 요소 | 구분 기호 | 의미 | 예 |
|---|---|---|---|
| **scheme** | `://` 앞 | 리소스에 접근하는 **방법·프로토콜** | `foo` (실제로는 http, https, ftp) |
| **authority** | `//` 뒤 ~ 경로 앞 | **사용자 정보, 호스트명, 포트** | `localhost:8080` |
| **path** | `/` 로 시작 | 서버 내 **자원의 경로** | `/over/there` |
| **query** | `?` 뒤 | 서버에 전달할 **추가 데이터**(키=값) | `name=ferret` |
| **fragment** | `#` 뒤 | 문서 **내부 특정 위치** | `nose` |

### (2) authority 상세
`[userinfo@]host[:port]` — 사용자 정보(선택), 호스트명(필수), 포트(선택).

## 3. 문제 풀이
그림의 번호: (1)=`foo`, (2)=`localhost:8080`, (3)=`/over/there`, (4)=`name=ferret`, (5)=`nose`

보기 **순서대로** 해당 번호를 쓴다.
| 보기 순서 | 구성 요소 | 해당 번호 |
|---:|---|:---:|
| 1번째 | **query** : 서버에 전달할 추가 데이터 | **4** |
| 2번째 | **path** : 서버 내 특정 자원 경로 | **3** |
| 3번째 | **scheme** : 접근 방법·프로토콜 | **1** |
| 4번째 | **authority** : 사용자 정보, 호스트명, 포트 | **2** |
| 5번째 | **fragment** : 문서 내 특정 위치 | **5** |

→ `4 3 1 2 5`

> **정답: `43125`**

## 4. 암기 포인트
- `scheme://authority/path?query#fragment` 순서 암기.
- `?` = query 시작, `#` = fragment 시작.
