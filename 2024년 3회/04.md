## 1. 문제에서 묻는 것
프레임 3개일 때 **LRU 페이지 교체 알고리즘**의 **페이지 부재(Page Fault) 횟수**를 구하는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 가상 메모리와 페이지 부재
실행 중인 프로그램의 데이터(**페이지**)는 **메모리의 프레임(칸)** 에 올라간다. 프레임은 제한되어 있다.
- 필요한 페이지가 프레임에 **있으면 적중(Hit)**
- **없으면 페이지 부재(Page Fault)** → 디스크에서 불러와야 함. 프레임이 가득 차 있으면 **어떤 페이지를 내보낼지(교체)** 정해야 한다.

### (2) 교체 알고리즘
| 알고리즘 | 내보내는 기준 |
|---|---|
| FIFO | **가장 먼저** 들어온 페이지 |
| **LRU** (Least Recently Used) | **가장 오래 전에 사용된** 페이지 (최근에 안 쓴 것) |
| LFU | 사용 **횟수가 가장 적은** 페이지 |
| OPT | 앞으로 **가장 오래 안 쓸** 페이지(이상적) |

LRU는 "최근에 쓴 것은 곧 다시 쓸 것"이라는 **시간 지역성**에 기반한다. **hit가 나면 그 페이지를 "가장 최근 사용"으로 갱신**하는 것이 핵심이다.

## 3. 풀이 (프레임 3개)
참조 순서: `7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1`
표에서 프레임은 **왼쪽이 가장 오래 전 사용, 오른쪽이 가장 최근 사용**.

| 번호 | 참조 | 프레임 상태 | 결과 |
|---:|---:|---|:---:|
| 1 | 7 | 7 | 부재 |
| 2 | 0 | 7 0 | 부재 |
| 3 | 1 | 7 0 1 | 부재 |
| 4 | 2 | (7 제거) 0 1 2 | 부재 |
| 5 | 0 | 1 2 0 | hit |
| 6 | 3 | (1 제거) 2 0 3 | 부재 |
| 7 | 0 | 2 3 0 | hit |
| 8 | 4 | (2 제거) 3 0 4 | 부재 |
| 9 | 2 | (3 제거) 0 4 2 | 부재 |
| 10 | 3 | (0 제거) 4 2 3 | 부재 |
| 11 | 0 | (4 제거) 2 3 0 | 부재 |
| 12 | 3 | 2 0 3 | hit |
| 13 | 2 | 0 3 2 | hit |
| 14 | 1 | (0 제거) 3 2 1 | 부재 |
| 15 | 2 | 3 1 2 | hit |
| 16 | 0 | (3 제거) 1 2 0 | 부재 |
| 17 | 1 | 2 0 1 | hit |
| 18 | 7 | (2 제거) 0 1 7 | 부재 |
| 19 | 0 | 1 7 0 | hit |
| 20 | 1 | 7 0 1 | hit |

부재: 1, 2, 3, 4, 6, 8, 9, 10, 11, 14, 16, 18 번 → **12번**

> **정답: `12`**

## 4. 암기 포인트
- LRU: **hit가 나도 그 페이지를 최신으로 갱신**해야 한다(5번에서 0이 가장 최근으로 이동).
- 교체 대상 = 프레임 안에서 **가장 오래 전에 참조된 것**.
