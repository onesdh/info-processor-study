# 문제 06

## 문제

다음은 GoF 디자인 패턴과 관련된 문제이다. 괄호안에 알맞는 용어를 작성하시오.

(        ) 패턴은 클래스나 객체들이 서로 상호작용하는 방법이나 책임 분배 방법을 정의하는 패턴이다.  
(        ) 패턴은 객체들 간의 통신 방법을 정의하고 알고리즘을 캡슐화하여 객체 간의 결합도를 낮춘다.  
(        ) 패턴은 Chain of Responsibility나 Command 또는 Observer 패턴이 있다.

행위

## 1. 문제에서 묻는 것
"클래스·객체들의 **상호작용 방법/책임 분배**를 정의", "Chain of Responsibility, Command, Observer" → GoF 디자인 패턴의 **3가지 분류 중 어디**인지 묻는 문제다.

## 2. 먼저 알아야 할 개념
### (1) GoF 디자인 패턴 3분류
| 분류 | 관심사 | 대표 패턴 |
|---|---|---|
| **생성(Creational)** | 객체를 **어떻게 만들까** | 싱글톤, 팩토리 메소드, 추상 팩토리, 빌더, 프로토타입 |
| **구조(Structural)** | 클래스·객체를 **어떻게 조합할까** | 어댑터, 브리지, 컴포짓, 데코레이터, 퍼사드, 플라이웨이트, 프록시 |
| **행위(Behavioral)** | 객체끼리 **어떻게 협력/책임을 나눌까** | **책임 연쇄**, **커맨드**, **옵저버**, 스트래티지, 템플릿 메소드, 상태, 이터레이터, 중재자, 메멘토, 방문자, 인터프리터 |

### (2) 행위 패턴의 예
- **Chain of Responsibility(책임 연쇄)**: 요청을 **처리할 수 있는 객체가 나올 때까지** 연결된 객체 사슬을 따라 전달
- **Command(커맨드)**: 요청을 **객체로 캡슐화**(실행 취소, 큐잉)
- **Observer(옵저버)**: 상태 변화를 **구독자에게 통지**

```text
 책임 연쇄:  요청 ─▶ [핸들러1] ─(처리불가)▶ [핸들러2] ─(처리불가)▶ [핸들러3: 처리]
```
## 3. 문제 풀이
| 문장 | 정답 |
|---|---|
| 상호작용 방법·**책임 분배** 방법 정의 | 행위 |
| 객체 간 **통신** 방법, **알고리즘 캡슐화**, 결합도 낮춤 | 행위 |
| Chain of Responsibility / Command / Observer | 행위 패턴의 종류 |

> **정답: 행위 (Behavioral) 패턴**

## 4. 암기 포인트
- **생성 = 만든다 / 구조 = 조합한다 / 행위 = 협력·책임**.
- 옵저버·커맨드·책임연쇄·스트래티지·템플릿메소드 → 모두 **행위**.
