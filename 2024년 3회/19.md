# 문제 19

## 문제

다음은 Java 코드에 대한 문제이다. 아래 코드를 확인하여 알맞는 출력값을 작성하시오.

```
class Main {

  public static class Collection<T>{
    T value;

    public Collection(T t){
        value = t;
    }

    public void print(){
       new Printer().print(value);
    }

   class Printer{
      void print(Integer a){
        System.out.print("A" + a);
      }
      void print(Object a){
        System.out.print("B" + a);
      }
      void print(Number a){
        System.out.print("C" + a);
      }
   }
 }

  public static void main(String[] args) {
      new Collection<>(0).print();
  }

}

```

## 1. 문제에서 묻는 것
**제네릭(Generics)과 메서드 오버로딩**이 결합된 문제다. `value`의 **컴파일 시점 타입**이 무엇인지에 따라 어떤 `print`가 선택되는지 알아야 한다.

## 2. 먼저 알아야 할 개념
### (1) 오버로딩의 선택 시점
오버로딩된 메서드는 **컴파일 시** 인자의 **선언된(정적) 타입**으로 결정된다. 실제 런타임 값의 타입은 고려하지 않는다.

### (2) 제네릭과 타입 소거(Type Erasure)
`Collection<T>`의 `T value`는 **컴파일 시 T로만 알려지며** 상한(bound)을 지정하지 않으면 **Object**처럼 취급된다. 즉 클래스 내부 코드가 컴파일될 때 `value`의 타입은 `T`(= Object로 소거)이다.
```java
public void print() { new Printer().print(value); }   // value의 컴파일 시 타입 = T (≈ Object)
```
### (3) 3개의 오버로드
| 메서드 | 매개변수 타입 |
|---|---|
| `print(Integer a)` | Integer |
| `print(Object a)` | Object |
| `print(Number a)` | Number |

선택 규칙: 인자의 **정적 타입에 적용 가능한 것 중 가장 구체적인 것**. 정적 타입이 `T(Object)`이면 `Integer`나 `Number`는 **적용 불가**(Object를 Integer로 자동 변환 불가) → `print(Object)`만 가능.

## 3. 실행 과정
```java
new Collection<>(0).print();   // T = Integer, value = 0 (런타임에는 Integer)
```
- `print()` 메서드는 **제네릭 클래스 안**에서 컴파일된다. 이때 `value`의 타입은 `T`.
- 컴파일러는 `T`에 대해 Integer/Number 오버로드를 쓸 수 없고 **`print(Object)`** 를 선택한다.
- 실행 시 `print(Object a)` → `"B" + a` → `"B" + 0` = **B0**

| 후보 | 적용 가능? | 이유 |
|---|:---:|---|
| `print(Integer)` | ❌ | T는 Integer임을 컴파일러가 모름 |
| `print(Number)` | ❌ | 마찬가지 |
| `print(Object)` | ✅ | T는 항상 Object |

> **정답: `B0`**

## 4. 암기 포인트
- **오버로딩은 컴파일 타임 타입**으로 결정 → 제네릭 `T`는 **Object**로 본다.
- 런타임 값이 `Integer`라도 `print(Integer)`가 선택되지 않는다.
