# 문제 01

## 문제

리팩토링의 목적에 대하여 서술하시오.

<details>
<summary><strong>정답 보기</strong></summary>

복잡한 코드의 단순화, 소스의 가독성을 통해 유지보수성 향상, 유연한 시스템, 생산성 향상, 품질 향상이 있다.

</details>



<details>
<summary><strong>상세 해설</strong></summary>

## 1. 문제에서 묻는 것
**리팩토링(Refactoring)의 목적**을 서술하는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 리팩토링이란?
**프로그램의 겉으로 드러나는 동작(결과)은 그대로 두고**, **내부 코드 구조를 정리·개선**하는 작업이다. 이미 작동하는 코드를 **깔끔하게 다듬는** 것이지, 기능을 추가하거나 버그를 고치는 것이 아니다.

```text
 [리팩토링 전]  중복 많고 길고 복잡한 코드  ─(동작 동일)─▶  [리팩토링 후]  짧고 읽기 쉬운 구조
```
### (2) 목적(효과)
| 목적 | 설명 |
|---|---|
| **가독성 향상** | 코드가 **읽기 쉬워짐**(이름 정리, 짧은 함수) |
| **복잡한 코드 단순화** | 중복 제거, 긴 메서드 분리 |
| **유지보수성 향상** | 수정·확장이 **쉬워짐** |
| **유연한 시스템** | 변경에 **잘 대응**하는 구조 |
| **생산성·품질 향상** | 버그 가능성 감소, 개발 속도↑ |

### (3) 대표 기법
메서드 추출(Extract Method), 변수명 변경(Rename), 중복 코드 제거, 클래스 분리 등.
리팩토링 후에는 **회귀 테스트**로 동작이 그대로인지 확인한다.

## 3. 서술 답안
> **리팩토링의 목적: 외부 동작은 유지한 채 복잡한 코드를 단순화하고 가독성을 높여 유지보수성을 향상시키며, 유연한 시스템 구조로 생산성과 품질을 높이는 것.**
