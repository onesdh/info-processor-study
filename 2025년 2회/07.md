# 문제 7

## 문제

다음은 디자인 패턴에 관한 문제이다. 아래 내용을 보고 알맞는 단어를 작성하시오.

어떤 객체에 대한 접근을 제어하거나 추가적인 기능을 부여하기 위해 해당 객체의 대리 객체를 사용하는 방식의 디자인 패턴이다.

실제 객체에 대한 접근 전에 필요한 작업을 수행할 수 있으며 실제 객체의 생성을 지연시켜 메모리와 자원을 절약할 수 있다.

또한, 실제 객체를 감추어 정보은닉을 강화할 수 있다는 장점이 있다.

## 1. 문제에서 묻는 것
"**대리 객체**로 접근을 제어/부가 기능, **생성 지연**, **정보 은닉**" → 어떤 디자인 패턴인지 묻는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 프록시(Proxy)란?
Proxy = **대리인**. 실제 객체(Real Subject)를 직접 쓰지 않고 **같은 인터페이스를 가진 대리 객체**를 앞에 세워 **접근을 중개·통제**한다. (GoF **구조 패턴**)

```text
 클라이언트 ──▶ [ Proxy ] ──(필요할 때만)──▶ [ 실제 객체 ]
                 ├ 접근 권한 검사
                 ├ 생성 지연(Lazy Loading)
                 └ 로깅·캐싱
```
비유: 대통령 **비서실**. 민원인은 비서를 거치고, 필요한 경우에만 대통령을 만난다.

### (2) 프록시의 활용 종류
| 종류 | 역할 |
|---|---|
| 가상 프록시 | **무거운 객체의 생성을 지연**(필요할 때 생성) → 메모리 절약 |
| 보호 프록시 | **접근 권한** 검사 |
| 원격 프록시 | **다른 서버의 객체**를 로컬처럼 사용 |
| 캐싱 프록시 | 결과를 **캐시**해 재사용 |

### (3) 비슷한 구조 패턴과 구분
| 패턴 | 목적 |
|---|---|
| **프록시** | **접근 제어**, 같은 인터페이스의 대리 |
| 어댑터 | **인터페이스 변환** |
| 데코레이터 | **기능 동적 추가** |
| 퍼사드 | 복잡한 하위 시스템에 **단순한 창구** 제공 |

## 3. 문제 풀이
| 단서 | 해당 |
|---|---|
| 객체에 대한 접근 제어, 추가 기능 / **대리 객체** 사용 | Proxy |
| 접근 전에 필요한 작업 수행, **생성 지연**으로 자원 절약 | 가상 프록시 |
| 실제 객체를 감춰 **정보 은닉** 강화 | Proxy |

> **정답: Proxy (프록시)**
