# 문제 1

## 문제

다음은 파일 구조와 관련된 설명이다. 설명을 읽고 괄호 안에 들어갈 가장 알맞은 용어를 작성하시오.

데이터베이스의 물리 설계 시, 레코드에 접근하는 방법은 순차 접근 방법, [   ] 방법, 해싱 방법 등이 있다.

이 중 [   ] 방법은 레코드의 키 값과 포인터를 쌍으로 묶어 저장하며 검색 시 키 값을 기준으로 빠르게 탐색할 수 있도록 설계되어 있다.

이 방식은 검색 속도가 빠르며 &lt;키 값, 포인터&gt; 쌍으로 구성된 자료 구조를 사용하여 해당 키가 가리키는 주소를 통해 원하는 레코드를 직접 찾을 수 있다.

| 접근 방법 | 설명 |
|---|---|
| 순차 접근 | 레코드를 처음부터 하나씩 검사 |
| [         ]  접근 | 키-값 쌍으로 구성되어 빠르게 검색 |
| 해싱 접근 | 해시 함수를 이용해 직접 주소 계산 후 접근 |

## 1. 문제에서 묻는 것
데이터베이스 물리 설계의 **레코드 접근 방법 3가지**(순차 / ? / 해싱) 중 "**키 값과 포인터 쌍**으로 빠르게 검색"하는 방법이 무엇인지 묻는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 접근 방법이란?
디스크에 저장된 수많은 레코드 중에서 **원하는 레코드를 어떻게 찾아가는가**의 방법이다. 책에서 내용을 찾는 방법과 비슷하다.

| 책에서 | DB에서 |
|---|---|
| 첫 장부터 한 쪽씩 넘겨 가며 찾기 | **순차 접근** |
| 맨 뒤 **색인(찾아보기)** 에서 단어 → 쪽 번호 확인 | **인덱스(색인) 접근** |
| 단어를 보고 계산해서 **바로 그 쪽**으로 이동 | **해싱 접근** |

### (2) 3가지 방법 비교
| 방법 | 동작 | 장점 | 단점 |
|---|---|---|---|
| **순차** | 처음부터 **하나씩 검사** | 구현 단순, 전체 처리에 적합 | 검색이 **느림** |
| **인덱스(색인)** | **<키 값, 포인터>** 쌍의 표(인덱스)를 만들어 **키로 검색 후 포인터로 레코드 직접 접근** | **검색 빠름**, 범위 검색 가능 | 인덱스 저장 공간·갱신 비용 |
| **해싱** | **해시 함수**로 키 → **주소를 직접 계산** | 키 검색 **매우 빠름** | 충돌 처리 필요, 범위 검색 불리 |

```text
 인덱스(키, 포인터)              데이터 파일
 ┌─────┬──────┐               ┌──────────────┐
 │ 키  │ 포인터 │               │ 레코드 1     │
 ├─────┼──────┤      ┌───────▶│ 레코드 2     │
 │ 10  │ ─────┼──────┘        │ ...          │
 │ 20  │ ─────┼───────────────▶ 레코드 n      │
 └─────┴──────┘               └──────────────┘
```
## 3. 문제 풀이
| 문제의 단서 | 해당 방법 |
|---|---|
| 레코드의 **키 값과 포인터를 쌍**으로 저장 | 인덱스 |
| 키 값 기준으로 **빠르게 탐색** | 인덱스 |
| <키 값, 포인터> 자료구조, 포인터가 가리키는 주소로 레코드를 **직접** 찾음 | 인덱스 |

표의 `[   ] 접근: 키-값 쌍으로 구성되어 빠르게 검색`도 같은 설명이다.

> **정답: 인덱스 (색인, Index)**

## 4. 암기 포인트
- **순차 = 처음부터**, **인덱스 = 키-포인터 표**, **해싱 = 계산해서 바로 이동**.
- 인덱스는 SQL에서 `CREATE INDEX`로 만든다.
