# 문제 10

## 문제

아래는 디자인 패턴에 관한 설명이다. 아래 설명을 읽고 보기에서 알맞는 용어를 작성하시오.

- 컬렉션 객체의 내부 구조를 노출하지 않고 순차적으로 접근할 수 있게 하는 패턴이다.  
- 이 패턴은 객체의 내부 표현 방식에 독립적으로 요소에 접근할 수 있도록 해준다  
- 반복 프로세스를 캡슐화하여 클라이언트 코드에서는 컬렉션의 구체적인 구현에 종속되지 않도록 한다.

|---|---|---|
| Singleton | Adapter | Iterator |
| Factory Method | Bridge | Visitor |
| Abstract Factory | Composite | Observer |

## 1. 문제에서 묻는 것
"컬렉션의 **내부 구조를 노출하지 않고 순차적으로 접근**" → 어떤 디자인 패턴인지 표(보기)에서 고르는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 이터레이터(Iterator) 패턴
리스트, 트리, 집합 같은 **컬렉션의 내부 구현을 모르고도** 원소를 **하나씩 차례로** 꺼낼 수 있게 해 주는 패턴이다. (행위 패턴)

```text
 클라이언트 ──▶ [ Iterator ]  hasNext() / next()
                    │ 순회 방법을 캡슐화
                    ▼
        컬렉션 (배열? 연결리스트? 트리?) ← 클라이언트는 몰라도 됨
```
```java
Iterator<String> it = list.iterator();
while (it.hasNext()) { System.out.println(it.next()); }   // ArrayList든 LinkedList든 동일하게 사용
```
### (2) 효과
- 컬렉션 **구현 방식을 바꿔도** 순회 코드는 그대로
- 순회 로직을 **한 곳에 캡슐화**
- 여러 순회 방식을 독립적으로 제공 가능

### (3) 보기 표의 패턴 분류
| 생성 | 구조 | 행위 |
|---|---|---|
| Singleton | Adapter | **Iterator** |
| Factory Method | Bridge | Visitor |
| Abstract Factory | Composite | Observer |

## 3. 문제 풀이
| 단서 | Iterator |
|---|---|
| **내부 구조를 노출하지 않고** 순차 접근 | ✅ |
| 내부 표현 방식에 **독립적**으로 요소 접근 | ✅ |
| **반복 프로세스를 캡슐화**, 구체 구현에 종속되지 않음 | ✅ |

> **정답: Iterator (이터레이터, 반복자)** — 행위 패턴
