# 문제 03

## 문제

다음은 디자인 패턴에 대한 설명이다. 괄호안에 알맞는 답을 작성하시오.

(기호식 보기가 있습니다. ex: Abstract Factory, Mediator 등)

(   1   )은/는 기능을 처리하는 클래스와 구현을 담당하는 추상 클래스로 구별한다.

구현뿐 아니라 추상화도 독립적 변경이 필요할 때 브리지 패턴을 사용한다.  
기존 시스템에 부수적인 새로운 기능들을 지속적으로 추가할 때 사용하면 유용하며,  
새로운 인터페이스를 정의하여 기존 프로그램의 변경 없이 기능을 확장할 수 있다.

(   2   )은/는 한 객체의 상태가 변화하면 객체에 상속되어 있는 다른 객체들에게 변화된 상태를 전달해주는 패턴이다.  
일대다 관계를 가지며, 주로 분산된 시스템 간에 이벤트를 생성·발행(Publish)하고, 이를 수신(Subscribe)해야 할 때 이용한다.

## 1. 문제에서 묻는 것
설명을 읽고 **디자인 패턴**(브리지, 옵저버)을 구분하는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 브리지(Bridge) — 구조 패턴
"**기능(추상화) 클래스**"와 "**구현 클래스**"를 **분리**하고, 둘을 **다리(bridge)** 로 연결한다. 그러면 **기능과 구현을 각각 독립적으로 확장**할 수 있다.
```text
 기능 계층                 구현 계층
 Remote ─────────────────▶ Device
  ├ BasicRemote               ├ SonyTV
  └ AdvancedRemote            └ LgTV
 (리모컨 종류를 늘려도 TV 코드 변경 없음, TV 종류를 늘려도 리모컨 코드 변경 없음)
```
상속만 쓰면 `Sony기본리모컨`, `LG고급리모컨`… 처럼 조합마다 클래스가 폭증한다. 브리지는 이를 막는다.

### (2) 옵저버(Observer) — 행위 패턴
한 객체(**Subject**)의 **상태가 변하면**, 그에 **의존하는 여러 객체(Observer)** 에게 **자동으로 알림**을 보낸다. **일대다(1:N)** 관계, **발행-구독(Publish-Subscribe)** 모델의 기반.
```text
 Subject ─ 상태 변경 ─▶ notify() ─▶ Observer A (갱신)
                                 └▶ Observer B (갱신)
```
예: 유튜브 구독 알림, 주가가 바뀌면 여러 화면 갱신, 분산 시스템의 이벤트 처리.

## 3. 문제 풀이
| 번호 | 단서 | 정답 |
|---|---|---|
| (1) | **기능 처리 클래스**와 **구현 담당 추상 클래스**를 구별, 구현·추상화의 **독립적 변경**, **브리지 패턴** | **Bridge** |
| (2) | 한 객체의 **상태 변화를 다른 객체들에게 전달**, **일대다**, **발행(Publish)·구독(Subscribe)** | **Observer** |

> **정답: 1. Bridge / 2. Observer**

## 4. 암기 포인트
- **브리지 = 구조(기능·구현 분리)**, **옵저버 = 행위(상태 변화 통지)**.
