<summary><strong>상세 해설</strong></summary>

## 1. 문제에서 묻는 것
"**하위 모듈부터 상위 모듈로** 진행하는 통합 테스트 방식"과, 그 방식에 필요한 **상위 모듈 대체 모듈**을 쓰는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 통합 테스트
단위 테스트를 마친 **모듈들을 합쳐서 모듈 간 인터페이스·호환성 문제**를 찾는 테스트.

### (2) 통합 방식
| 방식 | 설명 |
|---|---|
| 빅뱅 | 모든 모듈을 **한꺼번에** 통합 후 테스트 |
| **점증적** | 모듈을 **조금씩 추가**하며 테스트 |
| ├ **하향식(Top-Down)** | **상위 → 하위** 순서, **스텁(Stub)** 필요 |
| ├ **상향식(Bottom-Up)** | **하위 → 상위** 순서, **드라이버(Driver)** 필요 |
| └ 샌드위치 | 하향식 + 상향식 조합 |

### (3) 상향식과 드라이버
```text
        [ 상위 모듈: 아직 없음 ]  ←  테스트 드라이버가 대신 (하위 모듈을 호출·입출력 제어)
           /           \
   [ 하위 B: 있음 ] [ 하위 C: 있음 ]
```
- **테스트 드라이버**: 이미 존재하는 **하위 모듈**을 호출해 **데이터를 입력**하고 **결과를 확인**하는, **존재하지 않는 상위 모듈의 대체 인터페이스**.
- 반대로 **스텁**은 하향식에서 **없는 하위 모듈**을 대신해 **정해진 값만 반환**.

## 3. 문제 풀이
| 번호 | 단서 | 정답 |
|---|---|---|
| 1 | **하위 모듈부터 시작해 상위 모듈로** 테스트 | **상향식** (Bottom-Up) |
| 2 | **이미 있는 하위 모듈**과 **없는 상위 모듈**의 인터페이스 역할 | **테스트 드라이버** |

> **정답: 1. 상향식 2. 테스트 드라이버**

## 4. 암기 포인트
- **하향식 = 스텁**, **상향식 = 드라이버**.
- 드라이버는 하위 모듈을 **운전(drive)** 한다.
