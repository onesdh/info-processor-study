# 문제 15

## 문제

다음 중, 설명에 대한 괄호 ( ) 안에 들어갈 알맞는 답을 작성하시오.

( ) 다이어그램은 문제 해결을 위한 도메인 구조를 나타내어 보이지 않는 도메인 안의 개념과

같은 추상적인 개념을 기술하기 위해 나타낸 것이다.

또한 소프트웨어의 설계 혹은 완성된 소프트웨어의 구현 설명을 목적으로 사용할 수 있다.

( ) 다이어그램의 형식은 ( )를 포함하여 속성(attribute)과 메서드(method)가 있다.

## 1. 문제에서 묻는 것
"도메인 구조를 나타내 **추상적인 개념을 기술**, **속성(attribute)과 메서드(method)** 를 포함" → 어떤 UML 다이어그램인지 쓰는 문제다.

## 2. 먼저 알아야 할 개념
### (1) UML
**Unified Modeling Language**. 소프트웨어를 **그림으로 표현**하는 표준 모델링 언어. 의미가 명확해 소통이 원활하고, 전체 구조와 클래스 간 **의존성 파악**·**유지보수 문서**에 유용하다.

### (2) UML 다이어그램 분류
| 구분 | 성격 | 다이어그램 |
|---|---|---|
| **구조(Structure)** | **정적** | **클래스**, 객체, 컴포넌트, 배치, 복합체, 패키지 |
| **행위(Behavior)** | **동적** | 유스케이스, 시퀀스, 커뮤니케이션, 상태, 활동 |

### (3) 클래스 다이어그램
시스템을 구성하는 **클래스들과 그 관계**를 보여주는 **정적** 다이어그램. 클래스 상자는 **세 칸**으로 구성된다.
```text
 ┌──────────────┐
 │  클래스 이름   │   ← 클래스 이름
 ├──────────────┤
 │ - 이름 : String│   ← 속성(attribute)
 │ - 나이 : int   │
 ├──────────────┤
 │ + 말한다()     │   ← 메서드(method, 오퍼레이션)
 └──────────────┘
```
## 3. 문제 풀이
| 단서 | 클래스 다이어그램 |
|---|---|
| **문제 해결을 위한 도메인 구조**, 도메인 속 **추상적 개념** 기술 | ✅ |
| 소프트웨어 **설계** 또는 완성된 **구현 설명** 목적 | ✅ |
| 형식: **클래스(이름)** 를 포함하여 **속성과 메서드** | ✅ |

> **정답: 클래스 (클래스 다이어그램)**
