# 문제 20

## 문제

다음 아래의 내용을 보고 알맞는 용어를 작성하시오.

구체적인 클래스에 의존하지 않고 서로 연관되거나 의존적인 객체들의 조합을 만드는 인터페이스를 제공하는 패턴이다.

연관성이 있는 객체 군이 여러개 있을 경우 이들을 묶어 추상화하고, 어떤 구체적인 상황이 주어지면 팩토리 객체에서 집합으로 묶은 객체 군을 구현화 하는 생성 패턴이다

관련성 있는 여러 종류의 객체를 일관된 방식으로 생성하는 경우에 유용하다.

kit라고도 불린다.

## 1. 문제에서 묻는 것
"**구체적인 클래스에 의존하지 않고**, **관련 객체의 조합(제품군)** 을 만드는 인터페이스 / **kit** 라고도 불림" → 어떤 디자인 패턴인지 쓰는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 추상 팩토리(Abstract Factory) — 생성 패턴
서로 **관련 있는 객체들의 묶음(제품군)** 을 **구체 클래스 이름을 모른 채** 생성하게 해 주는 패턴이다. 공장을 바꾸면 **제품군 전체가 한꺼번에** 바뀐다.

```text
            ┌───────── 추상 공장 (UIFactory) ─────────┐
            │  createButton()    createCheckbox()     │
            └──────▲──────────────────────▲───────────┘
                   │                      │
           LightFactory               DarkFactory
        (LightButton+LightCheckbox) (DarkButton+DarkCheckbox)
 클라이언트는 UIFactory만 알고, 어떤 공장을 쓸지만 정하면 Light/Dark 세트가 통째로 교체됨
```
### (2) 비슷한 패턴과 구분
| 패턴 | 한 줄 정의 |
|---|---|
| **추상 팩토리** | **제품군(여러 종류의 객체 세트)** 생성, 별칭 **Kit** |
| 팩토리 메소드 | **한 종류** 객체 생성을 서브클래스에 위임 |
| 빌더 | 복잡한 객체를 **단계별 조립** |
| 싱글톤 | 인스턴스 **1개** 보장 |

## 3. 문제 풀이
| 단서 | Abstract Factory |
|---|---|
| 구체 클래스에 의존하지 않고 **연관 객체의 조합** 생성 | ✅ |
| 객체 군을 묶어 추상화, 상황에 따라 팩토리가 구현 | ✅ |
| 관련 있는 여러 종류 객체를 **일관되게** 생성 | ✅ |
| **kit**라고도 불림 | ✅ |

> **정답: Abstract Factory (추상 팩토리)**
