# 문제 03

## 문제

다음은 소프트웨어 모듈 간의 결합도(Coupling)에 대한 설명이다. 괄호 안에 들어갈 말을 보기에서 골라 기호로 쓰시오.

( )는 한 모듈이 다른 모듈 내부에 있는 변수나 기능을 직접 참조하거나 사용하는 경우에 발생하는 결합도로, 결합도 종류 중 결합 강도가 가장 높은 형태이다.

보기

ㄱ. 자료결합도 (Data Coupling)

ㄴ. 스탬프결합도 (Stamp Coupling)

ㄷ. 제어결합도 (Control Coupling)

ㄹ. 외부결합도 (External Coupling)

ㅁ. 내용결합도 (Content Coupling)

ㅂ. 공통결합도 (Common Coupling)

## 1. 문제에서 묻는 것
"다른 모듈 **내부**의 변수나 기능을 직접 참조", "결합 강도가 **가장 높은** 형태" → 어떤 결합도인지 고르는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 모듈과 결합도
- **모듈**: 프로그램을 기능별로 나눈 조각(함수, 클래스, 파일 등).
- **결합도(Coupling)**: 모듈끼리 **서로 얼마나 의존하는가**. 의존이 클수록 한 모듈을 고칠 때 다른 모듈도 같이 고쳐야 하므로 **결합도는 낮을수록 좋다.**

### (2) 결합도 6단계 (강도 순)
```text
 낮음(좋음) ◀──────────────────────────────────────────▶ 높음(나쁨)
 자료  <  스탬프  <  제어  <  외부  <  공통  <  내용
```
| 유형 | 의존 방식 | 예 |
|---|---|---|
| 자료(Data) | **값 하나씩**만 주고받음 | `add(3, 4)` |
| 스탬프(Stamp) | **구조체·배열·객체** 통째로 전달 | `print(student)` |
| 제어(Control) | 상대의 **흐름을 제어하는 값(플래그)** 전달 | `run(mode)` 의 mode가 분기를 결정 |
| 외부(External) | **외부 형식·장치·프로토콜**을 공유 | 같은 파일 포맷, 통신 규약 |
| 공통(Common) | **전역 변수**를 여러 모듈이 공유 | 모두가 `g_count` 수정 |
| 내용(Content) | **다른 모듈의 내부 코드·데이터를 직접 참조/수정** | 다른 모듈 안으로 `goto`, 내부 변수 직접 수정 |

## 3. 문제 풀이
- "다른 모듈 **내부**에 있는 변수나 기능을 **직접 참조**" = 캡슐화(정보 은닉)를 완전히 깨뜨리는 것 → **내용 결합도**.
- "결합 강도가 가장 높다" → 6단계 중 마지막인 내용 결합도와 일치.

## 4. 보기별 분석
| 보기 | 맞/틀 | 이유 |
|---|---|---|
| ㄱ 자료 | ❌ | 가장 **낮은** 결합도 |
| ㄴ 스탬프 | ❌ | 자료구조 단위로 주고받음 |
| ㄷ 제어 | ❌ | 플래그로 상대 흐름을 제어 |
| ㄹ 외부 | ❌ | 외부 형식·인터페이스 공유 |
| ㅂ 공통 | ❌ | **전역 변수** 공유 (내용 바로 아래 단계) |
| **ㅁ 내용** | ✅ | **내부 직접 참조** |

## 5. 암기 포인트
- 결합도 순서 암기: **자 · 스 · 제 · 외 · 공 · 내** (자스제외공내).
- 정답은 **양 극단(자료/내용)** 에서 많이 나온다.
- 짝 개념 **응집도**는 반대로 *높을수록* 좋다 (기능적 응집도가 최고).

> **정답: ㅁ. 내용결합도 (Content Coupling)**
