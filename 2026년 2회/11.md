# 문제 11

## 문제

다음은 GoF(Gang of Four) 디자인 패턴에 대한 설명이다. 괄호 안에 들어갈 알맞은 용어를 쓰시오.

( )는 서로 관련 있는 여러 객체(제품군)를 생성하기 위한 인터페이스를 제공하는 생성 패턴으로, Kit이라고도 불린다. 이 패턴을 사용하면 구체적인 클래스를 지정하지 않고도 연관된 제품군 전체를 한 번에 변경할 수 있다.

## 1. 문제에서 묻는 것
"관련 있는 **여러 객체(제품군)** 를 만드는 인터페이스 / 생성 패턴 / **Kit**이라고도 함" → 어떤 디자인 패턴인지 묻는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 디자인 패턴이란?
소프트웨어를 설계할 때 **자주 만나는 문제와 그 검증된 해결 방법**에 이름을 붙여 둔 것이다. 그중 **GoF(Gang of Four, 4명의 저자)** 가 정리한 **23가지 패턴**이 시험 범위다.

### (2) 3가지 분류
| 분류 | 관심사 | 대표 패턴 |
|---|---|---|
| **생성** | 객체를 **어떻게 만들까** | **추상 팩토리**, 팩토리 메소드, 빌더, 프로토타입, 싱글톤 |
| 구조 | 클래스·객체를 **어떻게 조합할까** | 어댑터, 브리지, 컴포짓, 데코레이터, 퍼사드, 플라이웨이트, 프록시 |
| 행위 | 객체끼리 **어떻게 협력할까** | 옵저버, 스트래티지, 템플릿 메소드, 이터레이터, 커맨드 등 |

### (3) 추상 팩토리(Abstract Factory)란?
"제품군(서로 어울리는 객체들의 세트)"을 만드는 **공장의 공장** 같은 개념이다.

예) UI 테마 — Light 테마 공장은 `LightButton`, `LightCheckbox`를, Dark 테마 공장은 `DarkButton`, `DarkCheckbox`를 만든다.
```text
            ┌────────── UIFactory (추상 공장) ──────────┐
            │ createButton()   createCheckbox()         │
            └───────▲─────────────────────▲─────────────┘
                    │                     │
            LightFactory            DarkFactory
        (LightButton, LightCheckbox)  (DarkButton, DarkCheckbox)
```
클라이언트는 **구체적인 클래스 이름을 모른 채** `UIFactory`만 사용하므로, 공장만 바꾸면 **제품군 전체가 한 번에 교체**된다.

## 3. 문제 단서와 대응
| 문제의 문장 | 추상 팩토리의 특징 |
|---|---|
| 관련 있는 여러 객체(제품군) 생성 인터페이스 | 제품군 단위 생성 |
| 생성 패턴 | 분류가 생성 패턴 |
| **Kit**이라고도 불린다 | 별칭이 **Kit** (암기 포인트) |
| 구체 클래스 지정 없이 제품군 전체 변경 | 공장 교체만으로 전체 변경 |

## 4. 비슷한 패턴과 구분
| 패턴 | 한 줄 정의 |
|---|---|
| **추상 팩토리** | **제품군(여러 종류의 객체)** 생성, 별칭 Kit |
| 팩토리 메소드 | **한 종류** 객체 생성을 **서브클래스에 위임**, 별칭 Virtual Constructor |
| 빌더 | 복잡한 객체를 **단계별로 조립** |
| 싱글톤 | 인스턴스를 **하나만** 유지 |

> **정답: 추상 팩토리 (Abstract Factory)**
