# 문제 14

## 문제

병행제어기법 중, 접근한 데이터에 대한 연산을 모두 마칠때까지 상호배제하는 기법을 무엇이라 하는지 작성하시오.

<details>
<summary><strong>정답 보기</strong></summary>

로킹

병행제어란 다중 프로그램이 이점을 활용하여 동시에 여러 개의 트랜잭션을 병행수행할 때, 동시에 실행되는 트랜잭션들이 데이터베이스의 일관성을 파괴하지 않도록 트랜잭션 간의 상호작용을 제어하는 것입니다.

병행제어기법 - 로킹, 타임 스탬프 순서, 최적 병행 수행, 다중 버전 기법

타임 스탬프 순서(Time Stamp Ordering) : 트랜잭션과 트랜잭션이 읽거나 갱신한 데이터에 대해 트랜잭션이 실행을 시작하기 전에 시간표(time stamp)를 부여하여 부여된 시간에 따라 작업을 수행하는 기법

최적 병행 수행(검증기법, 낙관적 기법) : 병행수행하고자 하는 대부분의 트랜잭션이 읽기 전용 트랜잭션일 경우, 트랜잭션 간의 충동률이 매우 낮아서 병행제어 기법을 사용하지 않고 실행되어도 이 중의 많은 트랜잭션은 시스템의 상태를 일관성 있게 유지한다는 점을 이용한 기법

다중 버전 기법 : 타임 스탬프의 개념을 이용한 기법으로 타임 스탬프는 트랜잭션 및 데이터들이 이용될 때의 시간을 시간표로 관리하지만 다중 버전 기법은 갱신될 때마다의 버전을 부여하여 관리하는 기법

## 1. 문제에서 묻는 것
"접근한 데이터에 대한 **연산을 모두 마칠 때까지 상호배제**하는 병행제어 기법" → **로킹**을 쓰는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 병행 제어(Concurrency Control)
여러 트랜잭션이 **동시에 실행**될 때, 서로 간섭해 **데이터의 일관성이 깨지지 않도록** 제어하는 것.
```text
 문제 상황(갱신 손실): T1이 잔액 100을 읽음 / T2도 100을 읽음 → T1이 +50 저장(150), T2가 -30 저장(70) → 최종 70 (T1 갱신이 사라짐)
```
### (2) 병행 제어 기법
| 기법 | 핵심 |
|---|---|
| **로킹(Locking)** | 데이터에 접근하기 전 **잠금(Lock)** 을 걸어, **연산이 끝날 때까지 다른 트랜잭션의 접근을 막음(상호 배제)** |
| 타임스탬프 순서 | 트랜잭션 시작 전 **시간표(timestamp)** 부여, **시간 순서**대로 처리 |
| 최적 병행 수행(검증, 낙관적) | 충돌이 드물다고 가정하고 **먼저 실행 후 커밋 때 검증** |
| 다중 버전 | 갱신 때마다 **버전**을 부여해 관리 |

### (3) 로킹
```text
 T1: Lock(X) ──▶ X 읽기/쓰기 ──▶ Unlock(X)
 T2:        Lock(X) 요청 → T1이 끝날 때까지 대기 ⏳ → 이후 Lock(X) 획득
```
- **공유 잠금(S, 읽기)**: 여러 트랜잭션이 함께 읽기 가능
- **전용(배타) 잠금(X, 쓰기)**: 한 번에 하나만
- 부작용: **교착 상태(Deadlock)** 가능

## 3. 문제 풀이
| 단서 | 로킹 |
|---|---|
| 접근한 데이터에 대해 **연산을 모두 마칠 때까지** | ✅ |
| **상호배제**(다른 트랜잭션 접근 차단) | ✅ |

> **정답: 로킹 (Locking)**
