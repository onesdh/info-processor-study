## 2. 비용 산정·일정·품질 모형
| 용어 | 내용 | 기출 |
|---|---|---|
| **LOC 기법** | 코드 라인 수로 노력 예측. **노력(인월) = LoC ÷ 1인당 월 생산량**, **기간 = 노력 ÷ 인원** (기출: (30,000/300)/5 = **20개월**) | [🔥 20년 1회 16번](../2020년 1회/16.md) |
| **COCOMO** | 보헴 모형, LOC → 노력. **조직형**(≤5만 줄, 중소 업무용) / **반분리형**(≤30만 줄, 유틸리티) / **내장형**(≥30만 줄, 초대형 시스템) | ⬜ |
| Putnam / SLIM | 생명주기 노력 분포(Rayleigh-Norden 곡선) | ⬜ |
| **기능점수(FP)** / ESTIMACS | 기능 요인 가중치 합 | ⬜ |
| **PERT** | 낙관·기대·비관 시간, **(낙관 + 4×기대 + 비관)/6** | ⬜ |
| **CPM** | **임계 경로**(가장 오래 걸리는 경로) | ⬜ |
| 간트 차트 | 작업 시작·종료 막대 | ⬜ |
| **CMMI** | 성숙도 5단계: **초기 → 관리 → 정의 → 정량적 관리 → 최적화** | ⬜ |
| **SPICE(ISO/IEC 15504)** | 능력 6단계: **불완전 → 수행 → 관리 → 확립 → 예측 → 최적화** | ⬜ |
| 프레임워크 | **재사용성·모듈화·확장성(다형성)**, **IoC(제어의 역흐름)** | ⬜ |

## 3. 형상(구성) 관리 [🔥 22년 3회 11번](../2022년 3회/11.md) 외 2회
- **SCM**: 변경 사항을 **체계적으로 추적·관리**. **4기능**: **형상 식별**(대상 정의) → **형상 통제**(**변경 요구 검토·승인, 형상통제위원회(CCB)**, 변경 활동 통제) → **형상 감사**(베이스라인 무결성) → **형상 기록**(상태 보고). (+버전 제어)
| 방식 | 내용 | 도구 |
|---|---|---|
| 공유 폴더 | 지역 컴퓨터의 공유 폴더, 변경은 DB에 기록 | RCS, SCCS |
| **클라이언트/서버** | **서버에 저장·서버에서 버전 관리** | **CVS, SVN** |
| **분산 저장소** | **원격 + 지역 저장소**, 로컬에서도 버전 관리 | **Git**(리누스 토발즈, 2005) |
- **Git 명령**: `init`(지역 저장소 생성) / `add`(스테이징) / `commit`(지역 저장) / `branch`(브랜치 생성) / `checkout`(브랜치 이동) / `push`(원격에 반영) / `fetch`(원격 변경 가져오기) / `clone`(원격 전체 복제). **Check-in** = 수정한 파일을 저장소에 반영 ⬜.
- **빌드 자동화**: **Jenkins**(Java 기반, 서블릿 컨테이너) / **Gradle**(Groovy, 안드로이드) / Ant / Maven / Make ⬜.
- ⚠ ATM·OLAP·DDoS·Cyber Kill Chain·OLTP는 **형상 관리 도구가 아님**.
