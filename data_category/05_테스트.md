## 2. 블랙박스 vs 화이트박스
| 구분 | 블랙박스 | 화이트박스 |
|---|---|---|
| 관점 | **내부 모르고** 명세·인터페이스로 | **소스 내부 논리 경로** |
| 기법 | **동치 분할 · 경계값 분석 · 원인-결과 그래프 · 오류 예측 · 비교 검사 · 결정 테이블 · 상태 전이** | **기초 경로 검사 · 제어 구조 검사 · 커버리지** |

### 화이트박스 커버리지 (약→강) [🔥 25년 3회 2번](../2025년%203회/02.md) 외 8회
| 커버리지 | 기준 | 기출 |
|---|---|---|
| **문장(구문)** | **모든 문장** 1회 이상 | [🔥 24년 3회 13번](../2024년%203회/13.md) 외 1회 |
| **결정(분기)** | **결정 전체**가 T/F, **모든 분기선** | [🔥 24년 3회 13번](../2024년%203회/13.md) 외 2회 |
| **조건** | **개별 조건식** T/F (결정 결과 T/F가 모두 나온다는 보장 ✕) | [🔥 23년 2회 6번](../2023년%202회/06.md) |
| 조건/결정 | 결정 + 조건 모두 | ⬜ |
| **MC/DC(변경 조건/결정)** | **각 조건이 단독으로 결과에 영향** (n+1개) | [🔥 24년 1회 14번](../2024년%201회/14.md) |
| 다중 조건 | **모든 조합**(2ⁿ) | ⬜ |
- **문장 커버리지 순서 쓰기(25-1-15)**: 제어 흐름도의 노드(문장/조건)에 코드를 하나씩 대응시킨 뒤, **모든 문장을 최소 1번 지나는 실행 순서**를 쓴다. `while(조건){ if(c) 문; a++; }` 이면 `초기화 → ②조건 → ③if조건 → ④if문 → ⑤a++ → ②조건(재검사) → ⑥return` 처럼 **조건 → 본문 → 증감 → 다시 조건 → 종료** 흐름이다.
- **기초 경로 검사**: 절차적 설계의 **논리적 복잡도**를 측정해 테스트 케이스 설계. **순환 복잡도 V(G) = 화살표(간선) 수 − 노드 수 + 2** ⬜.
- 제어 흐름 그래프 풀이: 판단(마름모) 2개 → **경로 2개**로 모든 분기선 통과 [🔥 25년 2회 11번](../2025년%202회/11.md) 외 2회.

## 5. 성능·품질 지표·도구
| 지표 | 정의 | 기출 |
|---|---|---|
| **처리량** | 일정 시간 동안 처리하는 일의 양(트랜잭션 수) | [🔥 20년 1회 19번](../2020년%201회/19.md) |

| 자원 사용률 | CPU·메모리·네트워크 | |
- **복잡도**(빅오): O(1) / O(log n) 이진 트리 / O(n) for문 / **O(n log n)** 힙·합병 정렬 / **O(n²)** 삽입·선택·버블 / O(2ⁿ) 피보나치 ⬜.
- **클린 코드**: 이해·수정이 쉬운 단순한 코드. **나쁜 코드**: **스파게티 코드**(로직 얽힘), **에일리언 코드**(문서·작성자 없는 오래된 코드). **원칙**: **가독성 · 단순성 · 의존성 배제 · 중복 최소화 · 추상화** ⬜.
- **정적 분석 도구**(실행 없이: pmd, cppcheck, checkstyle, SonarQube) / **동적 분석 도구**(**메모리 누수·스레드 결함**: Valgrind) [🔥 22년 1회 10번](../2022년%201회/10.md) 외 1회.
- **xUnit**: **JUnit**(Java), CppUnit, NUnit [🔥 22년 1회 12번](../2022년%201회/12.md). 기타: **STAF**(분산 환경 재사용), **FitNesse**(웹 기반 테스트 케이스), **NTAF**(FitNesse+STAF, 네이버), **Selenium**(웹 브라우저·다국어), **watir**(Ruby) ⬜.
- **APM**(애플리케이션 성능 관리): **리소스 방식**(서버 자원 감시: Nagios, Zabbix, Cacti) / **엔드투엔드 방식**(요청 흐름 추적: VisualVM, 제니퍼, 스카우터) ⬜.

- **연계 테스트 순서**: 테스트 케이스 작성 → 환경 구축 → 수행 → 결과 검증 ⬜.

### 2025년 3회 02번

[해설 보기](../2025년%203회/02.md)

다음은 소프트웨어 테스트 기법 중 하나에 대한 설명이다.

소프트웨어 테스트의 구조 기반(화이트박스) 기법 중 하나로,

결정 포인트(Decision Point) 내에 존재하는 모든 개별 조건식(Atomic Condition) 을 대상으로 하는 커버리지 기준이 있다.

하나의 결정문(예: if (A && B) 또는 if (X &gt; 10 || Y == 0)) 안에는

여러 개의 조건식이 포함될 수 있는데 이 커버리지는

각각의 조건식이 True와 False 두 가지 경우를 모두 한 번 이상 만족하도록

테스트 케이스를 설계해야 한다.

즉, 모든 개별 조건이 두 방향의 결과를 거쳐야 “커버되었다”고 판단하지만

그렇다고 해서 전체 결정식(Decision Expression) 의 결과(True/False)가

모두 수행된다고 보장하지는 않는다.

ㅁ. 다중 조건(Multiple Condition)

ㅂ. 문장(Statement)
