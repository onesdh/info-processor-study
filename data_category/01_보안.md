## 2. 네트워크 공격
### (1) 도청·위조·가로채기
| 공격 | 핵심 | 기출 |
|---|---|---|
| **스니핑(Sniffing)** | 패킷 **도청**, **수동적** 공격. 평문 ID/PW 유출. 대응: 암호화 | [🔥 20년 4회 7번](../2020년%204회/07.md) |
| **IP 스푸핑** | **출발지 IP 위조** | ⬜ |
| **ARP 스푸핑** | **위조 ARP 응답 → MAC 테이블 오염 → 중간자(MITM)**, LAN(2계층)에서만 | [🔥 21년 3회 4번](../2021년%203회/04.md) |
| DNS 스푸핑 | 위조 DNS 응답으로 가짜 사이트 유도 | ⬜ |
| **세션 하이재킹** | **인증된 세션(TCP 시퀀스 번호·세션 ID)을 가로챔**, RST로 정상 연결 종료 후 공격자가 이어받음. 대응: HTTPS, 세션 만료, 쿠키 Secure/HttpOnly | [🔥 25년 1회 1번](../2025년%201회/01.md) 외 1회 |

| 중간자(MITM) | 통신 중간에서 가로채 열람·변조 | ⬜ |

### (2) 서비스 거부(DoS/DDoS)
| 공격 | 기출 단서 | 기출 |
|---|---|---|
| **SYN Flooding** | **SYN만 대량 전송, ACK 미전송**, 연결 **대기 큐 고갈**. 대응: SYN Cookie | [🔥 25년 2회 19번](../2025년%202회/19.md) |
| **Land Attack** | **출발지 = 목적지 주소·포트**로 위조 → 자기 자신에게 무한 응답 | [🔥 20년 1회 9번](../2020년%201회/09.md) |
| **Smurf (Smurfing)** | 위조 ICMP Echo를 **브로드캐스트**로 보내 응답이 피해자에게 **증폭** | [🔥 24년 3회 5번](../2024년%203회/05.md) |
| **ICMP/Ping Flooding** | ping(**ICMP Echo Request**) 연속 전송 | [🔥 23년 1회 10번](../2023년%201회/10.md) |
| **Ping of Death** | **규격 이상의 큰** ICMP 패킷 | ⬜ |
| **Teardrop** | 조각(**Offset**) 값 조작 → 재조립 오류·과부하 | ⬜ |
| **DDoS** | **좀비 PC(봇넷)** 다수가 동시 공격(DoS는 공격자 직접). 도구: **Trin00(UDP Flooding), TFN, TFN2K, Stacheldraht(암호화 통신·자동 업데이트)** | ⬜ |

### (3) 웹·애플리케이션 공격
| 공격 | 핵심 | 기출 |
|---|---|---|
| **SQL Injection** | 입력값 미검증 → **악의적 SQL 삽입·실행**, 인증 우회·정보 탈취. 대응: **Prepared Statement**, 입력 검증, 최소 권한 | [🔥 20년 2회 14번](../2020년%202회/14.md) |
| XSS | 악성 **스크립트 삽입** → 다른 사용자 브라우저에서 실행(세션 탈취) | ⬜ |
| CSRF | 인증된 사용자가 **의도하지 않은 요청**을 전송 | ⬜ |
| **버퍼 오버플로** | 할당된 메모리 범위를 넘어 읽기/쓰기. 대응: **스택가드**(복귀 주소 앞에 값을 두고 변조 시 중단) | ⬜ |
| 하드코딩 | 암호화 키 등을 코드에 직접 기재 → 유출·무차별 대입에 취약 | ⬜ |
| 접근제어자 | `public/protected/default/private` — 캡슐화로 외부 접근 제한 | ⬜ |

> 시큐어 코딩 7분류(교재 확인 필요): ①**입력데이터 검증 및 표현**(SQL 삽입, XSS, 경로 조작, 운영체제 명령어 삽입 등) ②**보안 기능** ③**시간 및 상태** ④**에러 처리** ⑤**코드 오류** ⑥**캡슐화** ⑦**API 오용**. CSRF는 ①이 아니라 일반적으로 ②(보안 기능) 쪽으로 분류.

## 4. 암호
### 대칭키 vs 비대칭키
| 구분 | 대칭키(개인키) | 비대칭키(공개키) |
|---|---|---|
| 키 | **같은 키** | **공개키/개인키** 쌍 |
| 속도·키 분배 | 빠름 / 분배 어려움 | 느림 / 분배 쉬움 |
| 알고리즘 | DES, 3DES, **AES, SEED, ARIA, IDEA, SKIPJACK**, RC4(스트림), LFSR, TKIP | **RSA(소인수분해)**, **ECC(타원곡선, 짧은 키)**, **Diffie-Hellman(키 교환, 최초 공개키 알고리즘)**, ElGamal(이산대수), DSA |

### 2026년 1회 15번

[해설 보기](../2026년%201회/15.md)

다음은 특정 공격 기법에 대한 설명이다. 아래 내용을 읽고 해당하는 공격 기법을 [보기]에서 골라 쓰시오.

원본 데이터 파일은 별도로 존재하며, 공격자는 해당 파일의 경로를 가리키는 특수 파일을 생성한다. 프로그램이 임시 파일을 생성하는 순간을 틈타 해당 임시 파일을 미리 준비한 특수 파일로 교체한다. 이후 프로그램이 임시 파일의 존재를 확인하면 교체된 파일을 정상으로 인식하고 동작하게 된다.

공격 절차

1. 공격자는 실제 파일이 아닌, 특정 파일의 경로를 참조하는 특수 파일을 미리 준비한다.  
2. 프로그램이 임시 파일을 생성하는 시점을 노려 해당 임시 파일을 준비한 특수 파일로 교체한다.  
3. 프로그램이 임시 파일의 존재 여부를 확인할 때, 조건에 부합하면 정상으로 판단하고 동작하며 부합하지 않으면 임시 파일을 삭제한다.

### 2026년 1회 16번

공격자는 목표 대상이 업무 또는 관심사로 인해 자주 방문하는 합법적인 웹사이트를 사전에 파악한다.

피해자는 정상적인 사이트를 방문했을 뿐이므로 감염 사실을 인지하기 어렵다는 특징이 있다.

사용자가 새로운 사이트에 가입하지 않고 평소에 이용하던 서비스의 계정으로 로그인할 수 있게 해주는 기술이다.

다음은 TCP 통신 과정에서 발생할 수 있는 보안 취약점에 대한 설명이다. 이를 이용한 공격 기법으로 옳은 것은?

TCP는 연결을 수립하기 위해 클라이언트가 서버에 SYN 패킷을 보내고 서버는 SYN-ACK 패킷으로 응답한 후 클라이언트가 다시 ACK 패킷을 보내는 3-way-handshake 과정을 거친다.

이때 공격자는 클라이언트 역할로 수많은 SYN 패킷을 서버에 전송한 뒤 마지막 ACK를 고의로 보내지 않아 서버가 연결 대기 상태를 계속 유지하게 만든다.

이로 인해 서버의 연결 대기 큐가 가득 차면서 정상적인 접속 요청을 처리하지 못하게 되어 서비스 거부 상태가 발생한다.

**정답:** SYN Flooding

- ( ) 함수는 임의의 길이의 데이터를 고정된 길이의 데이터로 매핑하는 함수이다.  
- ( ) 함수는 큰 파일에서 중복되는 레코드를 찾을 수 있기 때문에 데이터베이스 검색이나 테이블 검색의 속도를 가속할 수 있다.
