# B. 개념 요약
> 표기: 🔥 = 기출(최신 위치 + 추가 횟수), ⬜ = 아직 안 나온 보충 개념.

## 1. 설계 기본 원리
| 용어 | 내용 | 기출 |
|---|---|---|
| **모듈화** | 기능을 모듈 단위로 분리, **결합도↓ 응집도↑** | ⬜ |
| **추상화** | 포괄적 개념부터 설계 후 구체화 (과정·자료·제어 추상화) | ⬜ |
| **단계적 분해** | 상위 개념을 하위로 나눔(**하향식**) | ⬜ |
| **정보 은닉** | 내부 절차·자료를 감춰 다른 모듈이 접근·변경 못 하게 | ⬜ |
| 협약(Contract)에 의한 설계 | **선행조건 · 결과조건 · 불변조건** | ⬜ |
| 아키텍처 패턴 | **레이어**(인접 계층끼리) / **클라이언트-서버** / **파이프-필터**(필터+파이프) / **MVC**(모델·뷰·컨트롤러) / **마스터-슬레이브**(병렬) / **인터프리터** | ⬜ |

## 2. 결합도 [🔥 26년 2회 3번](../2026년%202회/03.md) 외 5회
**자료 < 스탬프 < 제어 < 외부 < 공통 < 내용** (낮을수록 좋음)
| 유형 | 정답 단서 | 기출 |
|---|---|---|
| 자료 | **단순 자료 요소**(값)만 | ⬜ |
| **스탬프** | **배열·레코드·객체** 등 자료구조 전달 | [🔥 25년 1회 12번](../2025년%201회/12.md) 외 1회 |
| **제어** | **제어 신호(플래그)** 로 상대 내부 논리 제어, **권리 전도** | [🔥 24년 2회 16번](../2024년%202회/16.md) 외 1회 |
| 외부 | 한 모듈이 **선언한 데이터를 외부 모듈이 참조** | ⬜ |
| **공통** | **전역 변수** 공유·갱신 | [🔥 25년 1회 12번](../2025년%201회/12.md) 외 1회 |
| **내용** | **다른 모듈 내부 변수·기능 직접 참조·수정**(가장 강함) | [🔥 26년 2회 3번](../2026년%202회/03.md) 외 2회 |

## 3. 응집도 [🔥 26년 1회 20번](../2026년%201회/20.md) 외 4회
**우연 < 논리 < 시간 < 절차 < 교환(통신) < 순차 < 기능** (높을수록 좋음)
| 유형 | 정답 단서 | 기출 |
|---|---|---|
| 우연적 | **관련 없는** 요소들 | [🔥 24년 1회 3번](../2024년%201회/03.md) |
| 논리적 | **유사 성격** 처리 요소를 묶음(매개변수로 선택) | ⬜ |
| 시간적 | **같은 시점**에 처리되는 기능(초기화) | [🔥 24년 1회 3번](../2024년%201회/03.md) |
| **절차적** | 기능적 연관 없이 **정해진 순서대로** 실행 | [🔥 26년 1회 20번](../2026년%201회/20.md) 외 1회 |
| **교환(통신)적** | **같은 입력·출력**을 사용하는 서로 다른 기능 | [🔥 26년 1회 20번](../2026년%201회/20.md) 외 2회 |
| **순차적** | **한 활동의 출력이 다음 활동의 입력** | [🔥 24년 2회 9번](../2024년%202회/09.md) |
| **기능적** | **단일 목적**(가장 강함) | [🔥 26년 1회 20번](../2026년%201회/20.md) 외 2회 |
- **Fan-in**: 그 모듈을 **호출(제어)하는 상위 모듈 수**(들어오는 화살표) / **Fan-out**: 그 모듈이 **호출하는 하위 모듈 수**(나가는 화살표) [🔥 22년 2회 20번](../2022년%202회/20.md) 외 1회. Fan-in↑ 재사용, Fan-out↓ 권장.
- **공통 모듈 명세 5원칙**: **정확성·명확성·완전성·일관성·추적성**. **재사용 3종**: 함수·객체(소스) / **컴포넌트**(인터페이스 통신) / **애플리케이션** ⬜. **N-S 차트**(Chapin chart): 연속·선택·다중선택·반복 ⬜.
- **코드 종류** ⬜: **순차**(일련번호) / **블록**(블록별 번호) / **10진**(도서관) / **그룹 분류**(대·중·소) / **연상(니모닉)** / **표의 숫자(유효 숫자)** / **합성**.

## 4. 객체지향
- **구성**: 객체(속성+함수) / **클래스**(공통 속성·연산 집합) / **메시지**(동작 지시). **특징**: **캡슐화 · 상속 · 다형성 · 연관성** ⬜.
### SOLID [🔥 22년 2회 6번](../2022년%202회/06.md)
**SRP** 단일 책임 / **OCP** 개방-폐쇄 / **LSP** 리스코프 치환 / **ISP** **인터페이스 분리**(쓰지 않는 메서드에 의존 ✕, 큰 인터페이스를 작게) / **DIP** 의존 역전(추상에 의존).
### 객체지향 분석(OOA) 방법론
| 방법 | 특징 |
|---|---|
| **럼바우(Rumbaugh, OMT)** | **객체 → 동적 → 기능** 모델링, 그래픽 표기 |
| 부치(Booch) | 미시적·거시적 프로세스, 클래스·객체 식별 |
| 야콥슨(Jacobson) | **유스케이스** 강조 |
| 코드와 요르돈 | **E-R 다이어그램**으로 객체 행위 |
| 위르프스-브록 | 분석·설계 **구분 없음** |

### 럼바우 3모델 [🔥 21년 2회 15번](../2021년%202회/15.md)
| 모델 | 다이어그램 | 단서 |
|---|---|---|
| **객체(Object)** | **ERD·클래스** | **객체들 간 관계**(정보 모델링) |
| **동적(Dynamic)** | **상태 변화도(STD), 사건 추적도** | **시간 흐름**에 따른 제어·상호작용 |
| **기능(Function)** | **DFD** | **입력값이 출력값**이 되는 처리 |

## 5. 디자인 패턴 [🔥 26년 2회 11번](../2026년%202회/11.md) 외 13회
**GoF 23개 = 생성 5 + 구조 7 + 행위 11.** 범위: **클래스**(상속, Factory Method·Adapter·Interpreter·Template Method) / **객체**(합성, 나머지).
### 생성(Creational) — 객체를 만드는 방법
| 패턴 | 정답 단서 | 기출 |
|---|---|---|
| **Singleton** | **인스턴스 1개 보장**, 전역 접근, DB 커넥션 풀 | [🔥 23년 2회 11번](../2023년%202회/11.md) |
| **Factory Method** | **서브클래스가 생성할 객체 결정**, 부모에는 구체 클래스 숨김, **Virtual Constructor** | [🔥 21년 3회 16번](../2021년%203회/16.md) |
| **Abstract Factory** | **관련 객체의 제품군**을 구체 클래스 모른 채 생성, **Kit** | [🔥 26년 2회 11번](../2026년%202회/11.md) 외 1회 |
| **Builder** | 복잡한 객체를 **단계별 조립**, 생성 과정과 표현 분리 | ⬜ |
| **Prototype** | **원본 복제**, 생성 비용이 클 때 | ⬜ |
### 구조(Structural) — 클래스·객체를 조합
| 패턴 | 정답 단서 | 기출 |
|---|---|---|
| **Adapter** | **호환되지 않는 인터페이스 변환**(Target·Adaptee·Adapter), **wrapper** | [🔥 25년 1회 14번](../2025년%201회/14.md) |
| **Bridge** | **기능(추상화) 계층과 구현 계층 분리**·연결, 독립 확장 | [🔥 26년 1회 2번](../2026년%201회/02.md) 외 1회 |
| **Composite** | 단일·복합 객체를 **트리 구조**로 동일하게 | ⬜ |
| **Decorator** | 객체를 감싸 **기능을 동적으로 추가** | ⬜ |
| **Facade** | 복잡한 서브시스템에 **단순한 통합 창구** | ⬜ |
| **Flyweight** | 유사 객체 **공유**로 메모리 절약 | ⬜ |
| **Proxy** | **대리 객체로 접근 제어**, 생성 지연, 정보 은닉 | [🔥 25년 2회 7번](../2025년%202회/07.md) 외 1회 |
### 행위(Behavioral) — 객체 간 협력·책임
| 패턴 | 정답 단서 | 기출 |
|---|---|---|
| **Observer** | **상태 변화 → 의존 객체 자동 통지**, **일대다**, 발행-구독 | [🔥 26년 1회 2번](../2026년%201회/02.md) 외 2회 |
| **Visitor** | **구조는 두고 연산만 추가**, 합성 구조 원소 방문 | [🔥 23년 2회 11번](../2023년%202회/11.md) |
| **Iterator** | **내부 구조 노출 없이 순차 접근** | [🔥 24년 2회 10번](../2024년%202회/10.md) |
| Chain of Responsibility | 처리 못 하면 **체인을 따라 다음 객체로** | ⬜ |
| Command | 요청을 **객체로 캡슐화**(재사용·취소·로그) | ⬜ |
| Interpreter | **문법**을 정의해 해석(SQL, 프로토콜) | ⬜ |
| Mediator | 객체 간 복잡한 상호작용을 **중앙에서** 관리 | ⬜ |
| Memento | **특정 시점 상태 저장·복원**(Ctrl+Z) | ⬜ |
| State | 상태에 따라 **행동 변경** | ⬜ |
| Strategy | **교체 가능한 알고리즘 캡슐화** | ⬜ |
| Template Method | 상위에서 **골격**, 하위에서 세부 구현 | ⬜ |
- 출제 유형: **패턴 설명 → 이름**, **분류 질문(행위 패턴)**, 표에서 고르기.

## 6. UML [🔥 25년 3회 1번](../2025년%203회/01.md) 외 6회
- **구성 요소**: **사물(Things) · 관계(Relationships) · 다이어그램(Diagrams)**. **스테레오타입** `«…»`.
- **구조(정적)**: 클래스, 객체, 컴포넌트, 배치, **패키지**, 복합체 구조 / **행위(동적)**: 유스케이스, **시퀀스(순차)**, 커뮤니케이션, **상태**, 활동, 상호작용 개요, 타이밍.
### 패키지 다이어그램 [🔥 25년 3회 1번](../2025년%203회/01.md) 외 2회
**폴더 모양 패키지**, **점선 의존 화살표**, **«import»/«access»/«merge»**, 모듈화·재사용·의존 관계 설계.
### 클래스 다이어그램 [🔥 24년 3회 14번](../2024년%203회/14.md) 외 3회
클래스 = **이름 / 속성 / 오퍼레이션** 3칸. **연관 클래스**: 연관에 속성·오퍼레이션이 필요할 때. **인터페이스** = 구현해야 할 **오퍼레이션 집합** [🔥 22년 3회 17번](../2022년%203회/17.md) 외 1회.
| 관계 | 표기 | 의미 | 기출 |
|---|---|---|---|
| **연관** | 실선 | 지속적 연결 | [🔥 24년 3회 14번](../2024년%203회/14.md) |
| **일반화** | **속 빈 삼각형(자식→부모)** | **상속(IS-A)** | [🔥 24년 3회 14번](../2024년%203회/14.md) 외 1회 |
| **집약** | **속 빈 마름모 ◇** | 전체-부분, 부분 **독립** | [🔥 21년 3회 7번](../2021년%203회/07.md) |
| **합성(포함)** | **속이 찬 마름모 ◆** | 전체-부분, 부분 **종속** | ⬜ |
| **의존** | **점선 화살표** | **일시적 사용** | [🔥 24년 3회 14번](../2024년%203회/14.md) |
| **실체화** | 점선+속 빈 삼각형 | 인터페이스 구현 | ⬜ |
### 기타 다이어그램 ⬜

## 7. 요구사항·분석
- **요구사항 개발 프로세스**: **도출 → 분석 → 명세 → 확인**. **기능 / 비기능**(성능=응답 시간, 자원=메모리·CPU, **운영=로그·모니터링**, 신뢰성, 가용성, 유지보수성, 이식성, 보안) [🔥 26년 1회 4번](../2026년%201회/04.md) 외 1회.
- **분석 기법**: **DFD**(버블차트) / **DD**(자료 사전) / **HIPO**(입력·처리·출력) / CASE.

- **UX** = 사용자가 느끼는 **감정·경험**, **UI** = 접점 [🔥 21년 2회 2번](../2021년%202회/02.md).

다음은 디자인 패턴에 관한 문제이다. 보기에서 알맞는 답을 작성하시오.

1.

- 생성자가 여러 차례 호출되더라도 실제로 생성되는 객체는 하나이고 최초 생성 이후에 호출된 생성자는 최초의 생성자가 생성한 객체를 리턴한다.  
- 주로 공통된 객체를 여러개 생성해서 사용하는 DBCP(DataBase Connection Pool)와 같은 상황에서 많이 사용한다.

- 호스트 객체의 내부 상태에 접근할 수 있는 방법을 제공하여 호스트 객체에 연산을 추가할 수 있도록 한다.

## SOLID 원칙 (1회)

### 2022년 2회 06번

[해설 보기](../2022년%202회/06.md)

다음은 SOLID 원칙에 관한 내용이다. 괄호안에 알맞는 단어를 보기에서 고르시오.  
(실제 기출문제에서는 답의 보기가 주어집니다.(오답 중, SRP, LSP 등..))

( ) 은/는 클라이언트가 자신이 이용하지 않는 메서드에 의존하지 않아야 한다는 원칙이다.

( ) 은/는 큰 덩어리의 인터페이스들을 구체적이고 작은 단위들로 분리시킴으로써 클라이언트들이 꼭 필요한 메서드들만 이용할 수 있게 한다.

예를 들어 하나의 복합기에 프린터와 복사기, 팩스 메서드가 있는데 이 세가지 메서드는 같은 파일에 존재하므로 프린터 로직만 바뀌어도 복사기와 팩스도 재컴파일을 해야한다.

그러므로 ( ) 을/를 적용하여 로직이 바뀌어도 다른 메서드는 영향을 받지 않도록 해야한다.

<details><summary>정답 보기</summary>

**정답:** ISP (Interface Segregation Principle, 인터페이스 분리 원칙)

</details>
