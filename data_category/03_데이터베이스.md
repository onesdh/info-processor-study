# B. 개념 요약
> 표기: 🔥 = 기출(최신 위치 + 추가 횟수), ⬜ = 아직 안 나온 보충 개념.

## 1. DB 설계·스키마·데이터 모델
### DB 설계 절차 [🔥 26년 1회 3번](../2026년%201회/03.md) 외 3회
**요구조건 분석 → 개념적 설계 → 논리적 설계 → 물리적 설계 → 구현**
| 단계 | 핵심 | 산출물 |
|---|---|---|
| 요구조건 분석 | 요구 조건 **명세서** 작성 | 요구사항 명세 |
| **개념적 설계** | 현실 세계를 추상화, **DBMS 독립** | **E-R 다이어그램** |
| **논리적 설계** | 특정 DBMS의 자료구조로 변환, **정규화**, 트랜잭션 인터페이스 | 논리 스키마 |
| **물리적 설계** | **저장 구조·접근 경로(인덱스)**, 성능 | **테이블 정의서** |
| 구현 | 목표 DBMS의 **DDL**로 DB 생성, 트랜잭션 작성 | 실제 DB |

### DB 설계 단계 별칭
**요구사항 분석 → 개념적 설계(개념적 데이터 모델링, E-R) → 논리적 설계(논리적 데이터 모델링, 관계형 스키마·정규화) → 물리적 설계(물리적 데이터 모델링, 인덱스·저장 구조) → 구현**

### 3단계 스키마 [🔥 23년 1회 18번](../2023년%201회/18.md) 외 1회
| 스키마 | 관점 | 개수 | 단서 |
|---|---|---|---|
| **외부** | 사용자·응용 프로그래머 | 여러 개 | **서브 스키마**, 뷰 |
| **개념** | **조직 전체** | **1개** | 전체 논리 구조, 관계·제약조건·보안·무결성 규칙 |
| **내부** | 저장 장치 | 1개 | **물리 저장 구조**, 인덱스, 레코드 순서 |

### 데이터 모델 3요소 [🔥 21년 2회 3번](../2021년%202회/03.md) 외 3회
**구조**(정적 성질·개체 간 관계) / **연산**(데이터 처리 명세, 조작 기본 도구) / **제약조건**(저장 가능한 데이터의 논리적 제약).

### E-R 다이어그램 기호 [🔥 22년 3회 18번](../2022년%203회/18.md)
**용어: 개체집합 = 같은 속성을 공유하는 개체들의 모임(사각형) / 관계집합 = 개체 간 관계(마름모) / 관계집합의 속성 = 두 개체의 관계에서 생성되는 값을 저장하는 속성.** **사각형=개체, 마름모=관계, 타원=속성, 이중 타원=다중값 속성, 밑줄 타원=기본키, 실선=개체↔관계, 점선=관계↔관계의 속성**. 복합 속성(성명=성+이름).

## 5. 정규화
- **이상(Anomaly)** [🔥 22년 1회 5번](../2022년%201회/05.md) 외 1회: **삽입**(불필요한 값도 함께 삽입) / **삭제**(필요한 정보까지 연쇄 삭제) / **갱신**(일부만 수정되어 모순)
- **함수적 종속** [🔥 22년 2회 18번](../2022년%202회/18.md): X→Y. **완전**(복합키 전체) / **부분**(키 일부) / **이행**(X→Y→Z ⇒ X→Z)

| 정규형 | 조건 | 기출 |
|---|---|---|
| 1NF | **원자값** | ⬜ |
| **2NF** | **부분 함수 종속 제거**(완전 함수 종속) | [🔥 21년 2회 4번](../2021년%202회/04.md) |
| **3NF** | **이행 함수 종속 제거** | [🔥 26년 2회 20번](../2026년%202회/20.md) 외 5회 |
| BCNF | **모든 결정자가 후보키**(후보키가 겹칠 때 적용) | ⬜ |
| 4NF | **다치(다중값) 종속 제거** (A →→ B) | ⬜ |
| 5NF | **조인 종속** 제거 | ⬜ |
- 정규화는 **무손실 분해**여야 함(다시 조인해도 원본 복원).
- 풀이: ①복합키 찾기 ②FD 나열 ③키 일부 종속→2NF 위반, 이행 종속→3NF 위반, 비후보키 결정자→BCNF 위반. (기출: (고객아이디,강좌명)→강사번호, 강사번호→강좌명 ⇒ **3NF, BCNF 아님**)
- **반정규화** [🔥 24년 2회 2번](../2024년%202회/02.md) 외 2회: 성능·편의를 위해 정규화 원칙을 **의도적으로 깸**. 방법: **테이블 통합·분할, 중복 테이블 추가**(**집계 테이블**: 트리거로 갱신 / **진행 테이블** / **부분 테이블**), **중복 속성 추가**. 장점 JOIN 감소, 단점 **무결성 저하**, 과하면 오히려 성능 저하.

## 7. 트랜잭션·회복·병행제어
### ACID [🔥 22년 1회 2번](../2022년%201회/02.md) 외 4회
**원자성**(All or Nothing) / **일관성**(전후 DB 일관) / **독립성·격리성**(끼어들 수 없음) / **지속성**(영구 반영). **COMMIT**(확정) · **ROLLBACK**(오류 시 되돌림) · **SAVEPOINT**.

### 회복(Recovery) [🔥 22년 1회 2번](../2022년%201회/02.md) 외 1회
| 용어 | 설명 |
|---|---|
| **Redo** | **완료 기록이 있는** 트랜잭션을 로그로 **재수행** |
| **Undo** | **미완료** 트랜잭션을 로그로 **취소**·이전 값 복원 |
| **지연 갱신** | 커밋 전에는 **로그에만** 기록 → Redo만 필요 |
| **즉각 갱신** | **수행 중 바로 DB 반영** → **Undo·Redo 모두** 필요 |
| 체크포인트 | 검사점 **이전 트랜잭션은 회복 제외** |
| 그림자 페이징 | 현재/그림자 페이지 테이블, 로그 불필요 |
| 미디어 회복 | 디스크 손상 대비 |

### 병행 제어 [🔥 21년 2회 14번](../2021년%202회/14.md)
- 목적: **일관성 유지**. 문제: 갱신 손실, 오손 읽기, 모순성, 연쇄 복귀.
- **로킹**: **연산 완료까지 상호 배제**. **로킹 단위**가 크면 병행성↓·오버헤드↓, 작으면 병행성↑·오버헤드↑. **2PL**(확장→축소). **타임스탬프 순서**(시작 전 시간표, 시간 순서대로) / **최적(검증) 기법** / **다중 버전 기법**.
### 교착상태 ⬜
**4조건**: 상호배제·점유와 대기·비선점·환형(순환) 대기. 해결: **예방 / 회피(은행가 알고리즘) / 발견 / 회복**.

이 중 [   ] 방법은 레코드의 키 값과 포인터를 쌍으로 묶어 저장하며 검색 시 키 값을 기준으로 빠르게 탐색할 수 있도록 설계되어 있다.

| 접근 방법 | 설명 |
|---|---|
| 순차 접근 | 레코드를 처음부터 하나씩 검사 |
| [         ]  접근 | 키-값 쌍으로 구성되어 빠르게 검색 |
| 해싱 접근 | 해시 함수를 이용해 직접 주소 계산 후 접근 |

**정답:** 인덱스 (색인, Index)

## 관계해석 (1회)

### 2022년 2회 01번

[해설 보기](../2022년%202회/01.md)

( )은 /는 관계 데이터의 연산을 표현하는 방법으로, 원하는 정보를 정의할 때는 계산 수식을 사용한다.  
수학의 predicate calculus에 기반을 두고 있으며, 관계 데이터 모델의 제안자인 codd가 수학에 가까운 기반을 두고 특별히 관계 데이터베이스를 위해 제안하여 탄생하였다.

( ) /은/는 원하는 정보가 무엇이라는 것만 정의하는 비절차적 특성을 지니며, 튜블 ( )와/과 도메인 ( ) 이/가 있다.
