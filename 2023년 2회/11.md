# 문제 11

## 문제

다음은 디자인 패턴에 관한 문제이다. 보기에서 알맞는 답을 작성하시오.

1.

- 생성자가 여러 차례 호출되더라도 실제로 생성되는 객체는 하나이고 최초 생성 이후에 호출된 생성자는 최초의 생성자가 생성한 객체를 리턴한다.  
- 주로 공통된 객체를 여러개 생성해서 사용하는 DBCP(DataBase Connection Pool)와 같은 상황에서 많이 사용한다.

2.

- 호스트 객체의 내부 상태에 접근할 수 있는 방법을 제공하여 호스트 객체에 연산을 추가할 수 있도록 한다.  
- 이 패턴은 보통 합성 구조의 원소들과 상호 작용하는 데 사용되며, 기존 코드를 변경하지 않고 새로운 기능을 추가하는 방법이다.

보기

|---|---|---|
| Singleton | Adapter | Observer |
| Factory Method | Bridge | Strategy |
| Builder | Decorator | Visitor |

## 1. 문제에서 묻는 것
설명에 해당하는 **디자인 패턴 이름**을 보기에서 고르는 문제다. 1번은 객체를 하나만 만드는 패턴, 2번은 기존 코드 변경 없이 연산을 추가하는 패턴이다.

## 2. 먼저 알아야 할 개념
### (1) 보기 표 (GoF 패턴 3분류)
| 생성 패턴 | 구조 패턴 | 행위 패턴 |
|---|---|---|
| Singleton | Adapter | Observer |
| Factory Method | Bridge | Strategy |
| Builder | Decorator | Visitor |

### (2) 싱글톤(Singleton)
**인스턴스를 오직 1개만** 만들고 전역에서 공유한다. 생성자를 여러 번 호출해도 **최초 객체를 반환**한다.
```text
 new 호출 1 → 객체 생성 ─┐
 new 호출 2 → 기존 객체 ─┼─▶ [ 같은 하나의 객체 ]
 new 호출 3 → 기존 객체 ─┘
```
활용: DB 커넥션 풀, 설정 관리자, 로그 관리자.

### (3) 방문자(Visitor)
**객체 구조(트리 등)를 바꾸지 않고, 그 위에서 수행할 새 연산을 "방문자 객체"로 분리**해 추가하는 패턴이다.
```text
 [요소 A] ─accept(visitor)─▶ visitor.visit(A) ← 연산 로직은 방문자 안에 있음
 [요소 B] ─accept(visitor)─▶ visitor.visit(B)
 새 기능 = 새 Visitor 클래스만 추가 (요소 클래스는 수정 불필요)
```
호스트 객체의 **내부 상태에 접근**해 연산을 수행하며, **합성(Composite) 구조의 원소들**과 함께 자주 쓰인다.

## 3. 문제 풀이
| 번호 | 단서 | 정답 |
|---|---|---|
| 1 | 생성자를 여러 번 호출해도 **객체는 하나**, 최초 객체 반환, DBCP | **Singleton** |
| 2 | 호스트 객체 내부 상태에 접근해 **연산 추가**, 합성 구조의 원소와 상호작용, **기존 코드 변경 없이** 기능 추가 | **Visitor** |

> **정답: 1. Singleton / 2. Visitor**

## 4. 암기 포인트
- **싱글톤 = 인스턴스 1개 (생성 패턴)**, **방문자 = 구조는 두고 연산만 추가 (행위 패턴)**.
