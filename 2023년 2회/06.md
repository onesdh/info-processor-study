# 문제 06

## 문제

다음은 테스트 커버리지에 대한 내용이다. 내용을 보고 보기에 알맞는 기호를 고르시오.

- 프로그램 내에 있는 결정포인트 내의 모든 각 개별 조건식에 대한 모든 가능한 결과(참/거짓)에 대해 적어도 한번 수행한다.  
- 소프트웨어 테스트 수행시 소스코드를 어느 수준까지 수행하였는가를 나타내는 기준을 나타낸다.  
- 실제 업무에서는 다양한 툴을 사용하여 테스팅 수행한다.  
- True/False에충분한 영향을 줄 수 없는 경우가 발생 가능한 한계점을 지닌다.

## 1. 문제에서 묻는 것
"결정 포인트 내의 **각 개별 조건식**의 참/거짓을 적어도 한 번씩 수행", "True/False에 충분한 영향을 못 줄 수 있는 한계" → 어떤 커버리지인지 고르는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 용어
```c
if (A && B) { ... }      // 결정(Decision) = (A && B) 전체
                          // 조건(Condition) = A, B 각각
```
### (2) 커버리지 종류
| 커버리지 | 기준 |
|---|---|
| 구문 | 모든 문장 실행 |
| 결정(분기) | **결정 전체**가 T/F |
| **조건** | **개별 조건식**이 T/F 각각 |
| 조건/결정 | 결정 + 조건 |
| 변형(변경) 조건/결정 | 각 조건이 결과에 독립 영향 |
| 다중 조건 | 모든 조합 |
| 경로 | 모든 실행 경로 |

### (3) 조건 커버리지의 한계
`if (A && B)`에서 테스트 `(A=T,B=F)`, `(A=F,B=T)` 두 개면 A, B가 각각 T/F를 한 번씩 모두 나온다. 그러나 두 경우 모두 **A&&B = F**로, **결정 전체의 결과 T가 한 번도 나오지 않을 수 있다** → "True/False에 충분한 영향을 못 줌".

## 3. 문제 풀이
| 문장 | 해당 |
|---|---|
| 결정 포인트 내 **모든 개별 조건식**의 T/F를 한 번씩 | 조건 커버리지 |
| 소스코드를 어느 수준까지 수행했는지의 기준 | 커버리지 일반 설명 |
| 결정 결과(T/F)에 충분한 영향을 못 줄 수 있는 한계 | 조건 커버리지의 약점 |

> **정답: ㅇ. 조건 커버리지**

## 4. 암기 포인트
- **결정 = 전체 식**, **조건 = 개별 식**.
- 조건 커버리지의 약점 → 보완책이 **조건/결정 커버리지**.
