# 문제 09

## 문제

애플리케이션을 실행하지 않고, 소스 코드에 대한 코딩 표준, 코딩 스타일, 코드 복잡도 및 남은 결함을 발견하기 위해 사용하는 도구는 무엇인지 쓰시오.

정적 분석 도구

</details>

## 1. 문제에서 묻는 것
"애플리케이션을 **실행하지 않고** 소스 코드의 코딩 표준·스타일·복잡도·결함을 발견하는 도구" → **정적 분석 도구**를 쓰는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 정적 분석 vs 동적 분석
| 구분 | **정적 분석** | **동적 분석** |
|---|---|---|
| 프로그램 실행 | **실행 안 함**(소스 코드만) | **실행하며** 분석 |
| 찾는 것 | **코딩 표준·스타일 위반, 코드 복잡도, 잠재 결함, 보안 취약 패턴** | **메모리 누수, 스레드 결함, 성능 문제** |
| 시점 | 개발 **초기부터** 적용 가능 | 실행 가능한 상태 필요 |
| 도구 예 | pmd, cppcheck, checkstyle, SonarQube, FindBugs | Valgrind, 프로파일러 |

```text
 정적: 소스 코드 ──(실행 없이)──▶ 분석 도구 ──▶ 결함·위반 목록
 동적: 소스 코드 ──실행──▶ 동작 추적 ──▶ 결함 목록
```
## 3. 문제 풀이
| 단서 | 정적 분석 도구 |
|---|---|
| **애플리케이션을 실행하지 않고** 소스 코드 분석 | ✅ |
| **코딩 표준, 코딩 스타일, 코드 복잡도, 남은 결함** 발견 | ✅ |

> **정답: 정적 분석 도구 (Static Analysis Tool)**
