# 문제 04

## 문제

데이터베이스의 회복(Recovery) 기법 중 Rollback 시 Redo, Undo가 모두 실행되는 트랜잭션 처리법으로 트랜잭션 수행 중 갱신 결과를 바로 DB에 반영하는 기법은 무엇인가?

지연 갱신 회복 기법 :

트랜잭션의 부분 완료 상태에선 변경 내용을 로그 파일에만 저장

체크 포인트 회복 기법 :

장애 발생 시, 검사점(checkpoint) 이전에 처리된 트랜잭션은 회복에서 제외하고 검사점 이후에 처리된 트랜잭션은 회복 작업 수행

그림자 페이징 회복 기법 :

트랜잭션이 실행되는 메모리상의 current page table과 하드디스크의 shadow page table이용

미디어 회복 기법 :

디스크와 같은 비휘발성 저장 장치가 손상되는 장애 발생을 대비한 회복 기법

## 1. 문제에서 묻는 것
"**Rollback 시 Redo, Undo가 모두 실행**되며 트랜잭션 수행 중 **갱신 결과를 바로 DB에 반영**하는 회복 기법" → 즉각 갱신 회복 기법을 쓰는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 데이터베이스 회복(Recovery)
장애(시스템 다운 등)가 발생했을 때 DB를 **일관된 상태로 복구**하는 기술. **로그(Log)** 를 이용한다.

### (2) 회복 기법 분류
| 기법 | 핵심 |
|---|---|
| **로그 기반** | |
| ├ **지연 갱신** | 트랜잭션이 **부분 완료(커밋 직전)** 될 때까지 변경 내용을 **로그에만 저장**, 커밋 후 DB에 반영 → 실패 시 **Redo만 필요**(Undo 불필요) |
| └ **즉각 갱신** | 트랜잭션 수행 중 **갱신 결과를 바로 DB에 반영** → 장애 시 **Undo와 Redo 모두 필요** |
| **체크포인트** | **검사점 이전** 트랜잭션은 회복에서 **제외**, 이후 트랜잭션만 회복 |
| **그림자 페이징** | **현재 페이지 테이블**(메모리)과 **그림자 페이지 테이블**(디스크)을 이용(로그 불필요) |
| **미디어 회복** | 디스크 등 **비휘발성 저장 장치 손상**에 대비 |

### (3) 지연 vs 즉각
```text
 지연 갱신:  [로그에만 기록] ──커밋──▶ [DB 반영]      → 커밋 전 장애: 아직 DB 안 바뀜 → Undo 불필요
 즉각 갱신:  [DB에 바로 반영 + 로그 기록] ──▶ 커밋    → 커밋 전 장애: DB가 이미 바뀜 → Undo 필요, 커밋 후 반영 누락 → Redo 필요
```
## 3. 문제 풀이
| 단서 | 즉각 갱신 회복 |
|---|---|
| **Rollback 시 Redo와 Undo 모두** 실행 | ✅ |
| 수행 중 갱신 결과를 **바로 DB에 반영** | ✅ |
