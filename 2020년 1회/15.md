## 1. 문제에서 묻는 것
"문서 이름, 제품 이름, **버전 번호**, 릴리스 날짜, 노트 버전 등의 정보"에 해당하는 **릴리스 노트 작성 항목**을 쓰는 문제다.

## 2. 먼저 알아야 할 개념
### (1) 릴리스 노트(Release Note)
개발 과정에서 정리된 **릴리스 정보를 최종 사용자(고객)와 공유**하기 위한 문서. 제품의 **변경 사항·알려진 문제·사용법 변경** 등을 안내한다.

### (2) 릴리스 노트의 작성 항목
| 항목 | 내용 |
|---|---|
| **헤더(Header)** | **문서 이름(릴리스 노트 이름), 제품 이름, 버전 번호, 릴리스 날짜, 참고 날짜, 노트 버전** 등 |
| 개요 | 제품·변경의 간단한 설명 |
| 목적 | 이 릴리스의 목적(핵심 변경점) |
| 문제 요약 | 수정·개선된 문제 요약 |
| 재현 항목 | 문제를 재현하는 절차 |
| 수정/개선 내용 | 변경·개선된 상세 내용 |
| 사용자 영향도 | 사용자에게 미치는 영향 |
| SW 지원 영향도 | 지원 소프트웨어에 미치는 영향 |
| 노트 | 참고 사항 |
| 면책 조항 | 책임 한계 |
| 연락처 | 문의 방법 |

### (3) 작성 순서
모듈 식별 → 릴리스 정보 확인 → 개요 작성 → 영향도 체크 → 정식 릴리스 노트 작성 → 추가 개선 항목 식별.

## 3. 문제 풀이
| 단서 | 헤더 |
|---|---|

> **정답: 헤더 (Header)**
